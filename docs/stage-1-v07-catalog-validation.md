## Назначение и границы

[Валидатор](../tools/validate_gdd_v07.py) читает пять нормативных JSON-каталогов
и Server Config без записи в них. Python 3.10+ и стандартной библиотеки достаточно;
зависимости мода/Java Core не изменены. Валидатор не исправляет исходники.
25.10.2026 отдельным поручением пользователя исправлен V07-01 в GDD;
[решение и fingerprint](gdd-v0.7-reconciliation.md).

Доступны обычный текст и машинный JSON-отчёт с кодом, именем файла и JSON Pointer
каждой найденной ошибки. Exit code 0 означает отсутствие ошибок проверяемого
набора правил, 1 — отказ. Семантические ошибки накапливаются; неправильная
структура останавливает зависимые проверки с диагностикой, без ложного PASS.
Ошибка чтения, дубли JSON-ключей, NaN/Infinity/переполнение binary64,
некорректный UTF-8/одиночные суррогаты и файл более 2 MiB отклоняются.

Проверяется:

- baseline ID/версии geneSchema=2, expressionRules=2, morphologySet=2, graph=1,
  ссылки между ними и fingerprints из config/каталога expression;
- совпадение семейств, founders, rig и семейных генов во всех реестрах,
  23 общих гена, три HERITAGE, счёт пар каждого семейства и запрет мутации HERITAGE;
- семь узлов на семейство, все неупорядоченные пары, уникальность ID/пар,
  принадлежность родителей и ребёнка одному семейству, union исторических корней;
- допустимые варианты генов и полные неупорядоченные pairRules, числовые эффекты,
  известные статы/визуальные слоты и возрастные варианты;
- формы/roots/роли/семь статов контентного каталога, 21 mutation target,
  восемь заданий, пять элементов/заклинаний и ссылки на них;
- совпадение продублированных значений config/контента: вероятности трёх ступеней,
  предел одного события, Колыбель/рассеивание, гарантия магии, wild ARCANA,
  слоты способностей и границы генетических множителей. Вероятности эксклюзивных
  категорий проверяются по диапазону и сумме, bool не считается числом.

Проверка config ограничена используемыми связями. Полная схема параметров,
сочетания feature flags, storage/lifecycle semantics, reload и snapshots —
следующий runtime-этап. Инструмент не исполняет формулу фенотипа или эффекты
способностей, не проверяет реальные Role ID/3D-модули/API и не сертифицирует Hytale.
PASS этих проверок не заменяет приёмку всего содержимого GDD.

## Fingerprints и D11

Для этого пакета воспроизведено **наблюдаемое** представление fingerprints:
компактный JSON с сортировкой ключей, UTF-8, без ASCII-экранирования.
Его SHA-256 совпадает с четырьмя manifest-ссылками config и двумя ссылками
expression на graph/content. Pretty-printed байты файлов дают другие хеши.

Эта функция явно названа `snapshot_fingerprint`, а отчёт помечает конвенцию
как `observed-v0.7-compact-sorted-json; not RFC8785`. Это не решение о формате
runtime-реестров/GEN1 и не универсальный RFC8785 encoder: представления чисел,
сортировка Unicode и прочие требования JCS ещё требуют отдельного контракта
и независимых векторов D11. Новая транспортная схема не подменяется Python JSON.

## Запуск

Из репозитория:

```sh
python3 -B tools/validate_gdd_v07.py
python3 -B tools/validate_gdd_v07.py --json
python3 -B -m unittest discover -s src/test/python -p 'test_gdd_v07_validator.py'
./gradlew testGddCatalogValidator
./gradlew verifyGddCatalogs
```

`--directory` позволяет проверить копию пакета. Без него путь определяется
от расположения скрипта, а не текущего каталога. Gradle принимает альтернативный
интерпретатор через `-PpythonExecutable=/path/to/python3`; машинный путь не задан
в проекте. Запуск CLI из другого каталога работает тем же способом.

Обе Gradle-задачи отдельные: Python не стал обязательным условием обычного
`build` или runtime-мода. `verifyGddCatalogs` проходит после исправления V07-01;
обычная зелёная сборка не заменяет эту проверку.

реальный пакет и его неизменённая временная копия принимаются. Временное

родителей, чужую группу, неправильные child roots, потерянное pairRule,

сумму вероятностей, типы и ошибки ввода. Семантические повреждения проверяются
после пересчёта fixture-хешей: одного checksum недостаточно для их допуска.
