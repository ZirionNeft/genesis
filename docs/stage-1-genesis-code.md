## Модель и границы доверия

`GenesisBlueprint`: Genome, versioned family/rig/archetype/assetSet, 64-битный
cosmeticSeed и список ExtensionPayload. Все ссылки — ContentId + положительная
версия. У модели нет владельца, UUID особи/события, обучения, текущих ресурсов,
родословной, FrailtyOutcome или provenance. Generation seed — отдельное понятие;
случайный birth nonce в рецепт не добавляется.

`GenesisCodeCodec` разделяет чтение/запись и разрешение определений. Структурно
корректный неизвестный аллель/набор правил/extension schema сохраняется без
подмены и без обращения к реестрам. Это нужно для чтения и lossless-пересохранения
старых данных. Успешный decode/encode не означает, что новый рецепт разрешено
импортировать, скрещивать, мутировать или воплощать; игровой экспорт/операция
должны пройти отдельную проверку определений и прав.

ImmutableBytes копирует вход и каждую выдачу byte[], имеет сравнение по значению.
ExtensionPayload содержит extension ID/version, schemaVersion, kind и исходные
байты. Геном/пары и список расширений immutable; повтор одного extension ID,
включая разные версии в одном рецепте, запрещён.

## Текстовый формат

```text
GEN1-<BASE32>-<CHECKSUM>
```

BASE32 — алфавит `ABCDEFGHIJKLMNOPQRSTUVWXYZ234567` по
[RFC 4648 §§3.5, 6, 10](https://www.rfc-editor.org/rfc/rfc4648.html#section-6),
**без `=`**, пробелов, переносов, строчных букв или подстановок 0/O и 1/I.
Неиспользованные хвостовые биты нулевые; альтернативные длины/представления
отклоняются. Кодек не выполняет trim/исправление пользовательского ввода.

CHECKSUM — первые 8 байт SHA-256 **бинарного payload**, в виде 16 uppercase
hex-символов. Выбран стандартный алгоритм JDK без сторонних зависимостей,
для обнаружения случайной порчи и переносимых тестовых векторов. Это не
криптографическая подпись, доказательство происхождения, право спавна или
заслуга первооткрывателя. После произвольной правки можно вычислить новый checksum;
проверки содержимого и прав всё равно обязательны.

## Канонический бинарный payload v1

Все целые big-endian. `u16` — 2 байта, `u32` — 4 байта; версии/schemaVersion
ограничены **1..2147483647**, индексы словаря начинаются с 0. `ref` состоит
из `u16 dictionaryIndex` и `u32 version`. Косметический seed — ровно 8 байт
в дополнительном коде Java long; при переносе нужно сохранить весь битовый шаблон,
включая отрицательные значения, без преобразования через JS Number.

| Порядок | Поле | Представление |
| --- | --- | --- |
| 1 | wireVersion | u16 = 1 |
| 2 | genomeSchemaVersion | u16 = 1 |
| 3 | dictionaryCount | u16 |
| 4 | dictionary | count × (u16 длина + ASCII байты ID) |
| 5 | genetics ruleset | ref |
| 6 | family | ref |
| 7 | rig | ref |
| 8 | archetype | ref |
| 9 | assetSet | ref |
| 10 | 12 пар аллелей | 12 × (u16 firstIndex + u16 secondIndex) |
| 11 | cosmeticSeed | i64 |
| 12 | extensionCount | u16 |
| 13 | extensions | блоки по схеме ниже |

Словарь содержит **ровно использованные** ID, без дубликатов. Сортировка
лексикографическая по tuple `(namespace, path)`, как ContentId.compareTo,
а не по всей строке `namespace:path`. Например, `v:x` идёт перед `v-a:extra`.
ASCII выбран по уже принятому синтаксису ContentId; Java modified UTF не используется.

Порядок локусов схемы 1: FRAME, HEAD, LIMBS, APPENDAGE, PIGMENT, COVER,
MUSCLE, STAMINA, METABOLISM, SENSE, TEMPER, ARCANA. Пара неупорядоченная,
first<=second по ContentId; сортировка входной map на байты не влияет.

Каждый extension block: `ref(extension)`, `u32 schemaVersion`, `u8 kind`,
`u32 payloadLength`, затем исходные payloadLength байт. Kind 0=REQUIRED,
1=OPTIONAL_COSMETIC. Блоки отсортированы по extension ID; иные kind запрещены.
Внутреннюю схему payload знает только соответствующий provider; основной кодек
её не нормализует, не читает как JSON и не удаляет нераспознанные байты.

Ограничения v1:

- бинарный payload <= **65536 байт**;
- текстовый код <= **104880 символов**;
- словарь <= **128** ID, каждый 1..256 ASCII-байт;
- расширений <= **64**, один payload <= **16384 байт**.

Размеры проверяются до соответствующих выделений/записей. При decode длины
также сверяются с оставшимися байтами. Запрещены отрицательные длины,
недопустимые ссылки, лишние хвостовые байты и неканонические варианты.
Повторное кодирование decoded-модели должно дать исходные байты: это дополнительно
отклоняет неиспользованные ID, перестановки пар/расширений и скрытые нормализации.

## Версии и воспроизведение

ReproductionProfile — доверенное frozen-определение архетипа. Его версия связывает
family/rig/assetSet, конкретные immutable phenotype/morphology rules, доступные
планы внешности и обязательные extension key. Изменение этой связи требует
новой версии архетипа; нельзя менять определения под прежней версией.
Визуальный слой должен иметь полную семантическую карту, все его appearance refs
должны присутствовать в переданном asset manifest. Rig/ruleset/family сверяются
с frozen GeneticsCatalog. Конфликтующие required extension versions запрещены.

ReproductionResolver хранит один immutable контекст ревизии и проверяет рецепт
для IMPORT, SPAWN, BREED или MUTATE. Он возвращает Resolved/Rejected с причиной;
никаких NPC, событий, ресурсов или UUID при этом не создаётся.

- **EXACT** требует точного совпадения всех пяти versioned references рецепта.
  Если старая ревизия не загружена, VERSION_UNSUPPORTED. Старый контекст можно
  сохранить отдельно; выбор/долговременное хранение таких архивов ещё не реализованы.
- **GENETIC_CURRENT** явно выбирает текущий профиль того же archetype ID и
  текущий ruleset того же ID. Family/rig ID должны совпадать. Каждая пара
  аллелей сохраняется и валидируется по текущим определениям. Создаётся отдельный
  evaluationGenome с текущей ссылкой ruleset; source blueprint остаётся неизменным.
  Выбранные актуальные версии возвращаются через profile, факт изменений —
  definitionsChanged. Исходный код и cosmeticSeed не переписываются.

Ни один режим не переименовывает ID и не заменяет неизвестный аллель. Допуски
морфологии и clamp характеристик выполняются реальными чистыми resolver'ами.
Архетип не выводится из похожести модели/генома. Автоматических миграций нет:
неподдерживаемые wire/schema, переименование и неразрешимые определения дают отказ.
Несовместимое изменение wire требует новой версии формата и явного reader/migration,
без изменения смысла существующих GEN1 байтов.

Текущее разрешение проверяет **ссылки/manifest**, не наличие Hytale-файлов
и не результат клиента. Ассеты в тестовых профилях синтетические, визуальный
слой fixture только HEAD. Рабочий draft Клыкастых не получил производственный
ReproductionProfile: финальные D05/D06, все физические слои, косметические
варианты seed, реальные файлы/rig/hitbox ещё требуют контента и приёмки.

## Расширения и безопасный отказ

ExtensionRegistry регистрирует точный `(extension ID/version, schemaVersion)`
с authoritative kind и проверкой canonical payload. Builder проверяет логический
namespace регистратора, запрещает перезапись key и окончательно freeze'ится.
Namespace передаёт доверенный загрузчик; аутентификации внешних модов тут нет.

Проверка сначала требует все declared dependency payload из профиля и разрешает
метаданные **всех** блоков. Только после этого вызываются canonical validators.
Удаление обязательного блока или смена его флага не обходят профильный допуск.
Причины отказа: MISSING_REQUIRED_DATA, MISSING_EXTENSION, VERSION_UNSUPPORTED,
SCHEMA_UNSUPPORTED, KIND_MISMATCH, INVALID_PAYLOAD, VALIDATOR_FAILED.
Ошибка RuntimeException в validator даёт отказ, исходные байты не изменяются.

По умолчанию любое недоступное расширение отклоняет зависимый preflight,
даже если вход сам объявил его косметическим. Автоматический optional fallback
не реализован: он потребует отдельно доверенного разрешения и проверки,
что fallback не меняет геном. Одной недоверенной метки kind недостаточно.

После исчезновения provider код остаётся читаемым и пересохраняемым. После
возврата совпадающего определения он снова разрешается с теми же байтами/кодом.
Отказ относится к конкретному зависимому архетипу; базовый контент без этой
зависимости продолжает проходить проверку в том же контексте.

Реестр пока не подключён к живым сторонним плагинам. Validators обязаны быть
доверенными, чистыми, детерминированными и ограниченными по времени, без IO/
blocking/изменяемого внешнего состояния. Принудительные deadlines/scheduling
для внешних handlers и защита tick остаются D14/2A, не реализованы этим helper.
Полный workflow должен вызвать preflight до расхода и RNG; низкоуровневые pure
методы наследования/мутации сами не получают extension payload. Их оркестрация,
права, владение, provenance и идемпотентный commit ещё не подключены.

## Независимый тестовый вектор

Файл: [genesis-code-v1-vector.properties](../src/test/resources/genesis-code-v1-vector.properties).
Содержит полный payloadHex и полный GEN1 code, рассчитанные независимо
Python `struct`/`base64`/`hashlib`, без Java-кодека.

- ruleset `v:r@1`, family `v:f@1`, rig `v:q@1`, archetype `v:h@1`, assets `v:s@1`;
- по порядку 12 локусов: `v:a00/v:b00` ... `v:a11/v:b11`;
- cosmeticSeed=42;
- один REQUIRED extension `v:x@2`, schema=3, payload hex `00ff0100`;
- словарь 30 ID, **311 байт**, **520 символов кода**;
- checksum **881CF92C7DC1EF57**.

Это wire-fixture, не реальные игровые аллели/ассеты. Он фиксирует длины,
порядок, positive versions, 64-bit seed, opaque-байты и checksum.

## Проверки и состояние

30 новых тестов: 2 Base32, 12 codec, 7 registry, 9 reproduction.
Проверены RFC-векторы, независимый golden, знаковые границы seed, порядок
namespace/пар/extensions, opaque round-trip, checksum/несовместимые версии,
все усечённые префиксы, неканонический словарь/пары, неверные длины/индексы,
точный максимальный размер и превышения, snapshots/дубликаты/freeze,
1000 повреждений бинарного payload, обязательные зависимости, отсутствие/
возврат provider, canonical validation/failure, exact/current и автономность
базового архетипа при недоступном расширении.

`./gradlew build verifyPluginJar --console=plain`: **121 тест PASS**,
0 failures/errors/skipped. Все **44** Java-файла core отдельно компилируются
`javac --release 25` без Hytale/сторонних библиотек. Новых зависимостей нет.
Тестовый vector находится в test resources и не является игровым asset pack.
Сервер/мир/игровые ресурсы не менялись и не перезапускались.
