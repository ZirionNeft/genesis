## Источники и применимость

[MutationCatalog](../src/main/java/dev/ifelse/zirion/genesis/core/mutation/v2/MutationCatalog.java)
загружается CatalogLoader из нормативного content catalog и входит в immutable
CatalogBundle. Сохраняются content ID/SHA-256, точная gene schema и selection ID
`genesis:mutation-selection-v1`. В Java нет второй таблицы mutation ID/вариантов
или балансных вероятностей. Политика читается из удержанного ServerConfig.

Проверяются уникальные ID/цели, зарегистрированные изменяемые гены и варианты,
запрет HERITAGE, ровно одно магическое определение ARCANA→awake, selection method
и точные условия гарантии. Административное изменение условий в исходнике
с пересчитанными хешами не позволяет исполнить неподдержанный алгоритм.

Категории нормативного каталога: шесть косметических, девять физиологических,
пять поведенческих и одно магическое событие. Неблагоприятные варианты уже входят
в эти категории; отдельного броска beneficial/harmful из старого прототипа нет.

## Принятые детали алгоритма

GDD задаёт изменение после наследования и выбор допустимых mutation ID.
Для исполняемого контракта `genesis:mutation_evaluator` v2 зафиксировано:

1. Определение допустимо, если его ген присутствует, разрешает мутацию и хотя бы
   одна копия отличается от target. Уже целевая копия не выбирается повторно;
   пара target/target исключает это определение. Носительство одной копии допускает
   новое событие на второй. Это детали реализации, не изменение исходных JSON.
2. Обычный единичный category draw проходит интервалы cosmetic → physiological
   → behavioral → magical; остаток — отсутствие события. Вероятности берутся
   по base/discovery/mastery из snapshot config. Сравнение сохраняет точный
   бинарный draw как n/2^53, аналогично новому attempt workflow.
3. В выпавшей категории выбирается равномерно один **допустимый ID**, отсортированный
   по стабильному namespaced ID. Нет промежуточного выбора гена/силы эффекта.
   Если категория пуста, события нет: без повторного броска или переноса её веса.
4. Равномерно выбирается одна отличающаяся копия канонической входной пары.
   Меняется только она; индекс события относится к входной паре. Оба `nextInt`
   потребляются и при bound=1. После изменения геном снова проверяется схемой.

При обычном событии расходуются один `nextDouble` и два `nextInt`; без события
или при пустой выбранной категории — только category draw. При отсутствии любых
допустимых определений RNG не расходуется. HERITAGE и ELEMENT не входят в цели
нормативных мутаций. Родители, историческая форма и все остальные гены сохраняются.
Новое событие не гарантирует проявления рецессивного варианта.

## Исследовательский снимок и гарантия

[ResearchSnapshot](../src/main/java/dev/ifelse/zirion/genesis/core/mutation/v2/ResearchSnapshot.java)
содержит playerId/familyId, revision, tier, focused, provenance текущей операции,
число подходящих успехов и признак уже выданного первого открытия.
Это авторитетные серверные данные, не сведения, которым можно доверять из UI.

Рождение подходит для счётчика, когда одновременно:

- attempt успешен и обычное наследование уже зафиксировало quiet/quiet в ARCANA;
- focus включён в config, исследование группы — mastery, разведение направленное;
- первое открытие ещё не выдано; origin — BREEDING, не ADMIN/IMPORT.

Первые шесть подходящих успехов при штатной политике увеличивают счётчик даже
при отсутствии события либо косметической/другой немагической мутации. Если
магическая мутация возникает раньше, первое открытие предлагается сразу.
На седьмом подходящем успехе вместо обычного category draw выбирается MAGICAL;
всё ещё выбираются ID и одна копия. Дополнительного обычного события нет.
Порог читается из config; при уменьшении порога уже накопленный счётчик не сбрасывается.

Неудачные попытки, исследование ниже mastery, отсутствие фокуса, унаследованный awake и
уже выданное открытие не увеличивают этот счётчик. ADMIN/IMPORT не используют
гарантию и не получают first-discovery credit; обычный генетический расчёт остаётся
доступен для внутренних симуляций. Выключенный focus отключает гарантию/её счётчик,
но не обычные вероятности новых мутаций.

Новая магическая мутация при естественном разведении может предложить первое
открытие и вне направленного mastery. Само наследование уже существующего awake
не объявляется новым событием. Гарантия не меняет наследование или ELEMENT,
не выбирает заклинание и не создаёт плату/валюту возрождения.

Результат `DiscoveryUpdate` — **предложение CAS**, с player/family, expectedRevision,
новым числом и одноразовым award flag. Он не изменяет store. В 2A нужно атомарно
сохранить offspring/operationId, прогресс и outbox; конфликт revision требует
разрешения операции без повторной выдачи. Два параллельных расчёта одного снимка
не являются двумя разрешёнными наградами. Остальные открытия/XP/задания — этап 3.

## Полный чистый workflow

[BreedingMutationWorkflow](../src/main/java/dev/ifelse/zirion/genesis/core/breeding/v2/BreedingMutationWorkflow.java)
компонует прежний pre-mutation этап и новый evaluator. Его отдельный алгоритм —
`genesis:breeding_mutation_workflow` v2; старый `breeding_inheritance_workflow` v2
сохраняет значение промежуточного шага и свои векторы.

Request закрепляет breeding request и ResearchSnapshot. До attempt проверяется
семейство исследования; прочие генетические/режимные/extension-проверки делегированы
первой фазе. Отказ/неудача не вызывают мутации и не возвращают discovery update.
Успех возвращает `Conceived`: исходное наследование, итоговый геном, не более
одного Change, предложенный прогресс и **заново рассчитанный** потенциал.

Replay удерживает исходные config/catalog/parents/seed и исследовательский снимок,
версии обеих фаз, selection ID и нейтрального Java LCG48 mutation RNG. Повтор
создаёт свежий RNG от сохранённого mutation seed; reload и мини-игра его не меняют.
Неизвестные алгоритмы отклоняются. Старые frailty/8%/impact policies не подключены.

`Conceived` — полный **внутренний генетический кандидат**, не commit/предмет/NPC
или публичный паспорт. Для игрового рождения использовать полный путь, а не
финализировать промежуточный AwaitingMutation. Права/возраст/резервы/реальные
ассеты/Before/After и durable идемпотентность ещё относятся к 0A/1V/2A/2B.
Сериализация replay и новый GEN1 этим пакетом не реализованы.
