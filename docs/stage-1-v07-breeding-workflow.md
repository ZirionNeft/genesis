## Граница результата

[BreedingWorkflow](../src/main/java/dev/ifelse/zirion/genesis/core/breeding/v2/BreedingWorkflow.java)
— чистое Core-вычисление с тремя результатами:

- `Rejected(reason)` — отказ до любого RNG, без расхода попытки;
- `Failed` — неудачный attempt draw, без расчёта ребёнка;
- `AwaitingMutation` — унаследованный кандидат, который **ещё обязан пройти
  этап мутаций**; это не готовая Искра, blueprint для воплощения или commit.

Кандидат содержит исходный унаследованный геном, историческую форму,
генетический потенциал до мутации, прямые ссылки на родителей в PedigreeEntry
и отдельные mutation/cosmetic seed. Он не сообщает «мутаций нет» по умолчанию.
После будущей мутации потенциал нужно вычислить заново по итоговому геному.
Успешный draw не создаёт NPC, предмет, запись store или событие.

## Снимок операции и повтор

[BreedingContext](../src/main/java/dev/ifelse/zirion/genesis/core/breeding/v2/BreedingContext.java)
хранит полный immutable ServerConfig, CatalogBundle и config revision.
`ConfigurationRuntime.Snapshot.breedingContext()` передаёт удержанный снимок
в чистое ядро без импорта адаптера `config` из Core. Получать его нужно один
раз при начале операции; текущий active snapshot после reload его не заменяет.

Replay включает:

- версии workflow/seed scheme и ID алгоритмов RNG/наследования;
- operationId/offspringId, упорядоченные полные снимки родителей, их UUID,
  исторические идентичности с graph fingerprint и геномы со schema fingerprint;
- seed, readiness/environment, режим, score и проверенное число успехов группы;
- исходный context со всеми настройками/каталогами и обязательные зависимости.

Revision — диагностический номер, а не замена полному config. Результат удерживает
точные gene/expression/graph/morphology/content ссылки через каталог/потенциал.
Повтор создаёт свежие локальные RNG; неизвестный алгоритм даёт отказ без fallback.

Это **контекст в памяти**, не сериализатор журнала и не новый GEN1.
Durable сохранение исходов/снимков, CAS и возврат уже сохранённого результата по
operationId ещё нужны в 2A. Повторное вычисление само по себе не предотвращает
повторную выдачу награды. Для полного этапа мутаций дополнительно потребуется
зафиксированный исследовательский контекст игрока/группы, включая условия гарантии.

## Порядок вычисления

1. Проверить включённое разведение, разные UUID родителей и отдельный offspringId.
2. Отклонить любые extension payload/обязательные зависимости: их наследование
   пока не поддержано. Bytes остаются неизменными, включая optional cosmetic.
3. Проверить семейство, оба полных генома, исторические ссылки и включение
   генетической поддержки в исторические корни. Найти явную пару графа.
4. Проверить environment в границах config, доступность manual/auto и порог
   открытия auto. При выключенной manual mini-game auto доступен сразу,
   если сам auto включён. Отказы завершаются до первого draw.
5. Вычислить вероятность и cooldown по удержанному config, сделать один attempt
   draw, включая вероятность ноль. При неудаче остановиться до inheritance RNG.
6. При успехе наследовать по одной копии каждого гена от A и B, определить
   историческую/effective форму, исходный потенциал и прямые ссылки родителей.
   Вернуть `AwaitingMutation` с независимыми seed следующего этапа.

Вход readiness — нормированный коэффициент [0,1]. Источники readiness/environment,
возраст, controller/права, исходный NPC, резервы, cooldown-state и Before/After
проверяет будущий серверный слой. Число успехов и score также должны приходить
из авторитетного состояния; методы Core не аутентифицируют вызывающий код.
Проверки и дополнительные штрафы по степени родства отсутствуют; сведения
об отсутствии/наличии дальних предков не являются условием наследования.

## Вероятность, мини-игра и RNG

C выбирается по равенству **исторических form ID**: это формы пары graph v1.
EffectiveSignatureForm предназначен для генетического проявления/пассивов и
не подменяет исторический ID в этом сравнении. Все балансные значения C, cap,
environment, thresholds и cooldown берутся из Server Config. Коэффициенты
формулы `Qmanual = 0.90 + 0.25 × score/100` и `Qauto=1` заданы GDD §6.

Арифметика вероятности/cooldown — BigDecimal без промежуточного округления.
Score на пороге уменьшает cooldown и при уже достигнутом cap; minimum cooldown
применяется после уменьшения. Quote возвращается при успехе и неудаче;
его фактическое применение/фиксация относится к игровому workflow 2B.

Для сравнения сохраняется **точное бинарное** значение `nextDouble` как n/2^53,
без перевода вероятности в приближённый double. Успех только при draw < P;
равенство даёт неудачу. Это часть нового алгоритма повторения и проверяется
независимым Python Fraction. Смена score/режима меняет вероятность и cooldown,
но не inheritance stream или mutation/cosmetic seed.

Внутренний workflow: `genesis:breeding_inheritance_workflow`, версия 2.
Повторно используется нейтральный `GenerationSeed` scheme 1 и его неизменяемый
SHA-256/GENS-контракт; RNG — Java Random LCG48, наследование — namespaced gene-ID
order v2. Существующая метка frailty оставлена для исторического прототипа;
новый workflow её не вызывает. Это не поддержка генетической v1 или старого GEN1.
