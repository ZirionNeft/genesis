# D13: первичная проверка совместимости на Hytale 0.7.2

но runtime-принятие NPC/права/lifecycle ещё не приняты.

Дата: 15.10.2026. Основание: GDD v0.5 §§23.3.13, 24.3–24.4, 24.6, 24.10.
Статус решения D13: **OPEN**. Это результаты чтения закреплённого артефакта,

## Найденные механизмы

| Область | Подтверждено в артефакте | Практический предел вывода |
| --- | --- | --- |
| Именованные модификаторы | `server.core.modules.entitystats.EntityStatMap`: `getModifier(int, String)`, `putModifier(int, String, Modifier)`, `removeModifier(int, String)` | Можно адресовать свой вклад строковым ключом; namespace и права обеспечивает Genesis, а не тип `String` |
| Хранение вкладов | `EntityStatValue` хранит `Map<String, Modifier>`; `putModifier` заменяет запись по ключу, `removeModifier` удаляет только этот ключ; поле `Modifiers` входит в CODEC | Один фиксированный `genesis:*` ключ не создаёт несколько записей в map. Доставку обновлений, reload и сохранность чужого вклада ещё проверить в runtime |
| Семантика статов | `ModifierTarget` — MIN/MAX; `StaticModifier` поддерживает additive/multiplicative расчёт; `computeModifiers` пересчитывает пределы и ограничивает текущее значение ими | Нельзя объявлять этот API готовым модификатором любых скорости/урона/силы; для каждого показателя нужен отдельный подтверждённый путь |
| Жизненный цикл ECS | `component.system.RefSystem`: `onEntityAdded(ref, AddReason, store, commandBuffer)` и `onEntityRemove(ref, RemoveReason, store, commandBuffer)` | Есть точки наблюдения с причинами; они сами по себе не создают транзакцию Искры/расхода/события |
| Причины ECS | `AddReason`: SPAWN, LOAD; `RemoveReason`: REMOVE, UNLOAD, BUILDER_TOOLS_UNDO | LOAD можно отличать от SPAWN, UNLOAD от удаления. SPAWN не означает подтверждённое генетическое рождение или право первооткрытия |
| Сохраняемая внешность | `PersistentModel.getModelReference()`; `Model.ModelReference` содержит `getModelAssetId()`, `getScale()`, `getRandomAttachmentIds()` | Достаточно полей для сверки стенда без собственной БД; восстановление в клиенте пока остаётся отдельным сценарием |
| Снимок сущности | `EntityDumpCommand` вызывает `Store.copyEntity`, `EntityStore.REGISTRY.serialize`, пишет BSON как JSON в журнал | Штатный read-only путь наблюдения без повторного применения модели; dump загруженной сущности не доказывает её прежнюю выгрузку |
| Роль NPC | `NPCEntity.getRoleName()`, `getRole()`, `getActiveMotionControllerName()` | Это сигналы роли/поведения, не универсальное доказательство владельца или primary controller другого мода |

`NPCEntity` также имеет reservations, но они не объявлены протоколом межмодового
владения; не приравнивать `isReserved()` к primary controller. Отсутствие общего
контроллера в просмотренных сигнатурах не доказывает отсутствие любых сигналов
в остальных системах. Неизвестных NPC нельзя автоматически считать свободными.

## Следующие проверки до реализации 2A/2B

- Определить собственный явный маркер/controller и поддерживаемые внешние сигналы.
  Проверить отказ известному чужому контроллеру и консервативное поведение при
  неопределённости; не ставить маркер всем NPC при LOAD.
- На контролируемом NPC добавить два независимых stat modifier: свой и внешний.
  Повторить применение своего ключа, снять только его, выполнить reload/save/load;
  сверить отсутствие дубля и сохранность чужого бонуса, включая ограничение HP.
- Проверить реальные SPAWN/LOAD/UNLOAD, порядок загрузки компонентов и поток
  callbacks. Не путать выгрузку с отсутствием NPC в клиентском радиусе.
- Спроектировать транзакцию и post-commit доставку по D02/§24.6 отдельно от
  событий ECS: repeat request, pre-validation timeout, listener failure, рестарт.
- Проверить собственную основную модель и допустимые overlays без перезаписи
  чужого состояния. Поддержка attachments стенда не доказывает сосуществование
  с произвольным внешним renderer/AI.

Эти результаты разрешают сузить исследование, но не закрывают D13, D01 или
матрицу совместимости MVP. Новый формат сохранений, публичный API и внешние
адаптеры в этом исследовании не реализованы.

Актуализация 25.10.2026 по v0.7: [отдельный аудит 0A](stage-0-v07-api-audit.md)
и [инвентарь 12 видов](stage-0-v07-vanilla-inventory.json). Уточнены UUID,
role-change UNLOAD/LOAD и опасный default fallback стандартного disk resource
storage; добавлен opt-in read-only probe. D13 остаётся OPEN, 0A IN_PROGRESS.
Результаты выше сохраняют дату 15.10 и прежние границы; живой сервер/клиент
в новом пакете не запускались.
