## Генетический потенциал

`PhenotypeRules` — неизменяемый профиль конкретного анатомического архетипа,
с собственными ID/версией и точной ссылкой на frozen `GeneticsRuleset`.
Выбор архетипа вызывающим слоем и настройка его баланса ещё не реализованы.

- Ровно десять `Stat`: HEALTH, STRENGTH, DEFENSE, SPEED, STAMINA, AGILITY,
  LOAD, PERCEPTION, TRAINABILITY, METABOLISM.
- Для каждого показателя обязателен `Range(base, lower, upper)` с конечными
  `0 <= lower <= base <= upper`. Это семантические величины профиля;
  нормализация UI 0–100 и перевод в реальные единицы Hytale остаются адаптеру.
- Для каждого достижимого `(locus, expressionId)` обязателен `Effect`,
  включая явно пустой эффект. Неизвестные/чужие локусу выражения отклоняются.
  Ключ включает локус: одинаковый ID в разных таблицах не смешивает их вклады.
- Берётся только один итог таблицы экспрессии на локус; скрытые копии аллелей
  не добавляют бонусов. Модификаторы — доли, суммируемые с 1 перед умножением
  на базу, затем результат ограничивается границами. Отрицательные вклады
  выражают цену/слабость, отдельного скрытого множителя мутации нет.
- Взаимодействия перечисляются явно: уникальный namespaced ID, условия минимум
  по двум локусам и собственные модификаторы. Все условия проверяются по
  проявленным выражениям, каждое совпавшее взаимодействие применяется один раз.
  Порядок фиксирован по ID; неизвестные условия и дубликаты запрещены.
- Проявленная активная способность — `Optional<ContentId>` только эффекта
  ARCANA: ноль или одна. Генотип не переписывается ради способности.
  Определения умений, их цена и выполнение в игре остаются дальнейшей работой.

Расчёт соответствует `clamp(B * (1 + sum(g) + sum(I)), L, U)`.
Для сумм и произведений используется BigDecimal из конечных double-входов:
переполнение промежуточного double не превращает допустимый результат в NaN.
Профиль не гарантирует сбалансированность произвольных входных таблиц: цены
преимуществ, невозможность всех максимумов и числа D05 требуют контентной проверки.

## Текущая эффективность

`StatBlock` — полный неизменяемый набор конечных неотрицательных величин.
`potential.actual(training, condition, environment)` считает `S * T * H * E`
отдельно, без повторных генных вкладов и без изменения потенциала/генома.
Факторы могут быть больше 1 или равны 0. Переполнение конечного результата
отклоняется; промежуточные большие произведения и последующий нулевой фактор
обрабатываются корректно. Возраст, обучение, сытость и состояние не наследуются
этим методом. Расходы ресурсов/корма пока не реализованы.

## Сопоставление внешности

`MorphologyRules` — неизменяемая карта точных семантических `Signature` в
версионируемые `Appearance(id, version, rigId)`. Набор визуальных локусов
задаётся явно для конкретного слоя. Невизуальные локусы не меняют этот слой;
если ARCANA/SENSE или другой локус должен менять внешность, его необходимо
включить в соответствующий слой. Это не ограничение всей морфологии шестью
локусами или тремя деталями стенда.

`Appearance` пока является **ссылкой на план**, а не готовым Hytale ModelAsset.
Будущий адаптер обязан проверить существование/версии плана и его ассетов,
крепления, анимации и hitbox. Модульный и подготовленный цельный варианты могут
быть явными выходами разных сигнатур. Сам resolver ничего не подбирает по
похожести: возвращает `Resolved` или `Unsupported` с исходной сигнатурой.
Неверный геном/ruleset отклоняется до выбора. Случайность отсутствует.

Каждая зарегистрированная сигнатура содержит ровно объявленные локусы,
только достижимые выражения и план с указанным rig. `coverage()` сравнивает
число зарегистрированных сигнатур с произведением числа достижимых выражений
по выбранным независимым локусам; BigInteger исключает переполнение счётчика.
Полная семантическая карта не доказывает готовность реальных игровых ассетов.

Для шести физических локусов draft (FRAME, HEAD, LIMBS, APPENDAGE, PIGMENT,
COVER) существует **729 генотипических комбинаций и 486 разных сигнатур**.
Это не требование создать 486 отдельных файлов моделей: модульный план может
переиспользовать части. Проверена исчерпывающая синтетическая карта всех этих
комбинаций и обнаружение отсутствующей записи. Готового производственного
сопоставления draft с ассетами D01 нет: mixed-head, форма тела/конечностей,
покров и смешанный окрас требуют отдельного контентного решения. Геном ради
доступных wolf/fox/grey/orange не подменяется и не перебрасывается.
