## Доставка и запуск

Gradle `processResources` копирует ровно шесть нормативных JSON из `specs/`
в `genesis/catalogs/v0.7/` внутри JAR. Новых независимых копий исходных defaults
в репозитории нет. Подстановка manifest-переменных к этим файлам не применяется.
Тест проверяет полное совпадение их байтов с исходниками; все шесть файлов —
inputs Java test. Они не являются Hytale NPC/visual assets в Server/Common.

[CatalogLoader](../src/main/java/dev/ifelse/zirion/genesis/config/CatalogLoader.java)
читает пакет из classloader или явно указанного каталога. Все источники
проверяются до возврата immutable `CatalogBundle`: семейные схемы v2,
[типизированный hybridGraph v1](stage-1-v07-forms.md),
[исполняемые expression tables v2](stage-1-v07-phenotype.md),
[mutation catalog](stage-1-v07-mutations.md), default config,
content ID/SHA-256 и неизменяемые исходные байты для архивных этапов. Mutable Gson-объекты наружу не выдаются.

`GenesisPlugin.setup()` вызывает [RuntimeBootstrap](../src/main/java/dev/ifelse/zirion/genesis/config/RuntimeBootstrap.java).
Настройки берутся из ресурса; если в `getDataDirectory()` существует
**genesis-config.json**, читается полный операторский файл. Автоматической
генерации/перезаписи/слияния файла нет. Отсутствие файла разрешает packaged
defaults; существующий повреждённый/недоступный файл, каталог вместо файла
или сломанная ссылка дают отказ, а не молчаливый fallback.

Сначала проверяются packaged definitions. После исправления HORN_FORM исходный
пакет принимается и bootstrap публикует снимок в тестах. Любая ошибка определений
по-прежнему оставляет v0.7-контур без активной конфигурации с предупреждением;
операторский конфиг её не обходит. TestNPC/AnatomyProbe сохраняют прежний путь работы. Другие NPC,
мир, инвентари и состояние чужих модов этот bootstrap не меняет.

Загрузка при старте подключена в коде и проверена через bootstrap-тесты.
Реальный сервер/клиент в этом пакете не запускались; прохождение загрузки
в живом Hytale не заявляется.

## Настройки и проверка ввода

[ServerConfig](../src/main/java/dev/ifelse/zirion/genesis/core/config/ServerConfig.java)
описывает все поля текущего Server Config чистыми immutable Java records:
режимы/флаги, лимиты, storage, taming, breeding, Sparks, growth, XP, progression,
summon/death/revival, mutation tiers, registry pins, guide и balance.
Числа defaults не захардкожены второй таблицей. Десятичные значения — BigDecimal;
коллекции копируются. Из nullable значений поддерживается только `maxRevives`:
null — без лимита, ноль/положительное число — допустимые квоты, отрицательное — отказ.

[ConfigLoader](../src/main/java/dev/ifelse/zirion/genesis/config/ConfigLoader.java)
отображает JSON в закрытую record-схему: обязательны все поля, неизвестные поля
отклоняются, строки/boolean не преобразуются в числа. `native` отображается на
Java-компонент `nativeStorage`; единственный допустимый null задан явно.
Поддержаны enum-значения текущего контракта, без выдуманных новых режимов.
Секрет PostgreSQL не читается: хранится только имя ссылки, значение не логируется.

Проверяются диапазоны вероятностей/долей, сумма эксклюзивных категорий ≤1,
порядок fear/environment/cooldown, таймауты, длительности, novelty-множители,
лимиты XP/veteran и согласование ролевых слотов между секциями. Включённое
разведение требует хотя бы одного режима. Не допускаются две Искры за успех,
старт без резерва, материальный возврат при рассеивании, отказ от strong/fail-closed
хранилища/backup и автоматическая миграция провайдера. Реализация провайдеров
и игровых действий остаётся отдельной работой; валидный флаг их не создаёт.

Чтение JSON использует строгий Gson из закреплённого серверного JAR 0.7.2.
API strictness подтверждён компиляцией и исполнением тестов на этом артефакте;
новых dependency declarations нет. **Gson используется в адаптере `config`,
Core его не импортирует.** Отклоняются дубли ключей, комментарии/нестрогий JSON,
неверный UTF-8/одиночные суррогаты, нечисловые значения, числовое переполнение,
вложенность >64, файл >2 MiB. Это пределы чтения ресурсов, не лимиты GEN1.
Ошибки содержат код и путь; значения конфигурации/секреты в сообщение не выводятся.

## Fingerprints: ограниченный профиль D11

[DesignFingerprint](../src/main/java/dev/ifelse/zirion/genesis/config/DesignFingerprint.java)
сверяет уже назначенные хеши этого исходного пакета по компактному sorted UTF-8
JSON-представлению, выявленному предыдущей сверкой. Текущий поддержанный профиль:
ASCII-ключи объектов, обычные десятичные числовые токены с ограниченной точностью
и диапазоном. Важны различия целого `6` и floating `6.0`. Пробелы/порядок ключей
не меняют результат; литеральные Unicode-строки сохраняются.

Экспоненциальные токены, не-ASCII ключи, высокая числовая точность и значения
вне этого профиля дают `FINGERPRINT_PROFILE`; угадывания общего canonicalization
нет. Все четыре supplied registry fingerprints и ссылка content проверены
по независимым хешам из исходных JSON. Это узкий verifier пакета v0.7, **не
универсальный Python JSON serializer и не RFC8785/GEN1 encoder**.
[Новый GEN1](stage-1-v07-genesis-code.md) отдельно канонизирует закрытую payload-схему
по JCS и сохраняет назначенные registry hashes. Общий fingerprint-профиль будущих
новых реестров/архив остаётся частью D11. Исходные JSON, их версии и fingerprints
не переопределяются транспортной канонизацией.

## Публикация и reload

[ConfigurationRuntime](../src/main/java/dev/ifelse/zirion/genesis/config/ConfigurationRuntime.java)
публикует `Snapshot(revision, config, catalogs)` одним AtomicReference-переходом.
Начатая операция должна удерживать свой snapshot. Чтение/проверку reload вызывать
вне tick/world thread; в CAS-цикле нет I/O, событий или игровых побочных эффектов.
Команды reload/permission flow для игроков ещё не зарегистрированы.

Перезагрузка config может менять будущую вероятность/таймауты/режимы, но
не изменяет старые снимки или каталоги. Изменение registry ID/version/SHA-256,
генетических границ phenotype либо неисполняемой текстовой novelty-policy
отклоняется; для изменения генетических правил нужен явный путь миграции.
Обычный reload также запрещает изменение storage-настроек: провайдер/файл БД/
секрет подключения не могут незаметно переключиться на другое хранилище.
Начальный выбор провайдера читается при bootstrap; проверки реальной идентичности
store при перезапуске и процедура его миграции ещё относятся к 2A.
Горячей замены definitions нет. При ошибке чтения/типов/инвариантов/пинов active
snapshot остаётся тем же объектом. Конкурентные успешные reload получают
уникальные возрастающие revision.

`Snapshot.knowledgeService()` создаёт [чистый механизм знаний/раскрытия](stage-1-v07-knowledge.md)
с удержанными настройками GEN1 и bundle. Он не хранит знания и не выдаёт
реальные permissions. Перед отправкой ответа игровой адаптер должен сверять
актуальные права/политику; старый снимок не обходит их отзыв.

Это фиксация настроек, а не авторизация рождения: controller/права/доступность
NPC, Before/After, резервы и атомарный commit должны проверяться будущим workflow.

25.10.2026 добавлен `Snapshot.wildContext(policy)` для
[генератора диких кандидатов](stage-1-v07-wild-candidates.md). Он удерживает
WildArcana/revision/bundle и требует явную политику распределений, которой нет
среди packaged игровых defaults. Неизвестный wild distributionVersion даёт отказ
при создании этого контекста; reload не перебрасывает существующего кандидата.

Тем же днём bundle дополнен [типизированным каталогом signature passives](stage-1-v07-signature-passives.md):
все 28 форм/requiredRole/описания, точные fingerprints как у expression tables.
Машинных effect-полей в источнике нет, тексты не исполняются. Пять новых loader-тестов
проверяют эти определения и сохранение прежних immutable-снимков.
