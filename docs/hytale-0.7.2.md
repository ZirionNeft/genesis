# Переход на Hytale 0.7.2

Дата: 15.10.2026. Целевая версия проекта — ровно `0.7.2`.
Версия Genesis остаётся `0.1.0-SNAPSHOT`; концептуальный GDD не изменяется.

## Официальные источники

- [Хотфиксы Update 7](https://hytale.com/news/2026/10/hotfixes-update-7):
  0.7.1 — 13.10.2026, 0.7.2 — 14.10.2026.
- [Release Maven metadata](https://maven.hytale.com/release/com/hypixel/hytale/Server/maven-metadata.xml):
  проверено напрямую 15.10.2026, `latest`/`release` = `0.7.2`, обе версии опубликованы.

0.7.1 исправляет подключение/переподключение, разрыв при переходе через портал
с летящим снарядом, появление крупных NPC через spawn markers и запуск Node Editor
на Windows/Linux. Для markers добавлен `MaxVerticalSpawnOffset` (до 32 блоков):
по умолчанию используется `MaxDropHeight`, новый предел не может быть меньше него.
Стенд Genesis не использует естественные spawn markers, поэтому менять его роль
из-за этого поля не требуется.

0.7.2 исправляет падение мира при загрузке старых goblin spawn beacons из Update 6,
падение Linux-миров с RocksDB, условия создания Backpack Upgrade II и загрузку
region instance `Zone1_Plains1`. В патчноуте не заявлено изменений контрактов
моделей/attachments, но это проверено отдельно по серверному артефакту.

## Артефакт и API

Проверен официальный `com.hypixel.hytale:Server:0.7.2`:

- `Implementation-Version: 0.7.2`;
- revision `d769dc3d57881261a62858e1394f0e4de9a21eca`;
- Java 25.

Сравнение публичных сигнатур 11 классов стенда между 0.7.0 и 0.7.2 не выявило
изменений. Дополнительно побайтово совпали 17 исследованных `.class`:
`Model`, `ModelReference`, `ModelAsset`, `ModelAttachment`, `ModelComponent`,
`PersistentModel`, системы ModelChange/SetRenderedModel/UpdateBoundingBox,
`TargetUtil`, `AnimationUtils`, `BasicCustomUIPage`, `StateSupport`, `Role`,
`ActionModelAttachment`, `BuilderSensorState` и `AbstractPlayerCommand`.
Это подтверждает исследованный серверный путь, но не заменяет проверку клиента,
протокола и ассетов на новой сборке.

## Изменения и проверки

- В `gradle.properties` закреплена `hytaleVersion=0.7.2`; зависимость compileOnly,
  runtime-сервер получают эту версию автоматически, а `ServerVersion` в манифесте —
  точный диапазон `=0.7.2`.
- Подсказка отсутствующего `Assets.zip` в `runServer` использует закреплённую
  версию вместо жёстко указанной 0.7.0.
- README, AGENTS и инструкция стенда указывают новую цель; результаты запусков
  0.7.0 сохранены с датой и не выдаются за проверку 0.7.2.
- Прежний dev-сервер 0.7.0 штатно остановлен перед переходом.
- `./gradlew build` под 0.7.2 после исправления манифеста: успешно; компиляция,
  упаковка, `PluginManifestTest` и `verifyPluginJar` прошли, сборка через IDEA успешна.
- После обновления Launcher 15.10.2026 локальный JAR 0.7.2 побайтово совпал с Maven;
  сервер и `Assets.zip` обновлены вместе, время изменения 03:46 MSK.
- Запуск 0.7.2 с новым Assets.zip успешен: плагин и pack Genesis загружены,
  две Generic-роли прошли NPC validation, авторизация восстановлена;
  `/auth status` и `/genesisprobe --help` проверены. Журнал:
  `run/logs/2026-10-15_03-49-57_server.log`.
- Клиентская приёмка стенда начата на 0.7.2: пользователь подтвердил исправление
  креплений головы и хвоста для `wolf fox grey 1`, затем смену частей, окраса,
  движение и открытие UI без замеченных проблем. Полная матрица сочетаний, hitbox,
  права/переводы/закрытие UI, наблюдатель и сохранение ещё не подтверждены;
  этап 0 — `IN_PROGRESS`, D01 — `OPEN`. По просьбе пользователя сервер остановлен,
  дальнейшая работа ожидает новых указаний.

## Уточнение формата ServerVersion

Первый запуск новой установки выявил пропущенное сборочной проверкой ограничение
`SemverRange`: bare `0.7.2` не является допустимым диапазоном для ненулевого patch.
Сервер отклонил весь манифест до загрузки плагина и asset pack. Корректное значение
для точной версии — `=0.7.2`; шаблон теперь явно добавляет `=`.

Проверка равенства JSON-строки в `verifyPluginJar` дополнена тестом настоящего
`PluginManifest.CODEC`: тест читает манифест из готового JAR и проверяет, что диапазон
принимает 0.7.2 и отвергает соседние patch/minor. Тест использует серверный JAR
в тестовой JVM с обязательным `HytaleLogManager`; HytaleServer не попадает в мод.

Оставшиеся клиентские сценарии — в [stage-0-anatomy.md](stage-0-anatomy.md);
выполнять после новых указаний пользователя.
Прежний мир сохранён; загрузка сервера не означает приёмку внешности и поведения NPC.
