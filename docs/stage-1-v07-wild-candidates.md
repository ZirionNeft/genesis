## Граница механизма

[WildGenomeGenerator](../src/main/java/dev/ifelse/zirion/genesis/core/wild/WildGenomeGenerator.java)
принимает исходный вид, фиксированный seed, явный признак affinity, идентичность
существующего NPC и предложенный candidateId. Он создаёт отдельную запись
кандидата с полным скрытым геномом и исторической формой исходного вида.
Все шесть HERITAGE-копий принадлежат этому виду; остальные пары проходят полную
семейную схему v2. Семейные гены учитываются, гибрид не допускается как дикий
исходный вид. Данные совместимы с новыми inheritance/form/phenotype resolver'ами.

Это предложение для будущего первого добровольного осмотра: генератор не
изменяет ванильное существо, не создаёт его копию, не назначает возраст/XP,
владельца или controller и не выдаёт публичный паспорт. Каталог из 12 видов
не доказывает наличие соответствующих NPC, rig или анимаций в Hytale.
Фактический допуск видов остаётся проверкой 0A.

## Явная политика частот

[WildDistributionPolicy](../src/main/java/dev/ifelse/zirion/genesis/core/wild/WildDistributionPolicy.java)
— отдельный immutable-вход с ID/версией/SHA-256 и точным pin geneSchema.
В этом пакете **нет принятой игровой политики или packaged defaults частот**.
Тестовая `test:wild_fixture` находится только в тестах и не подключена в плагине.
Не использовать её значения для игрового баланса.

Для каждого включённого исходного вида обязательны таблицы всех допустимых
неупорядоченных пар каждого гена, кроме HERITAGE и ARCANA. Каждая вероятность
неотрицательна, сумма ровно один; запрещённая политикой пара требует явного нуля.
Пропуск гена/пары, чужой вариант или лишний семейный ген дают отказ. Отдельно
задаются условные веса awake/awake и awake/quiet, также включая явный ноль.
Можно настроить только часть исходных видов; для остальных нет fallback.

ARCANA получает **одну проверку на кандидата**. Вероятности и distributionVersion
берутся из удержанного `ServerConfig.WildArcana`; поддержан текущий
`genesis:wild-arcana-v1`, неизвестный ID даёт отказ при создании контекста.
При непробуждении пара quiet/quiet, при пробуждении применяется условная таблица.
Поэтому частота пробуждённых кандидатов совпадает с configured rate и не
увеличивается из-за независимых попыток на обе аллели. ELEMENT выбирается из
своей явной таблицы, без подбора заклинания или переписывания при проявлении.

Открытые продуктовые решения: частоты всех остальных пар, дозировка пробуждённой
ARCANA, списки и источник affinity-тегов. Ядро получает affinity извне и не
выдумывает его по биому/имени NPC. Эти решения нужны до включения игрового осмотра.

## Детерминизм и версии

[WildGenerationContext](../src/main/java/dev/ifelse/zirion/genesis/core/wild/WildGenerationContext.java)
удерживает revision, значения WildArcana, весь проверенный bundle и политику.
`ConfigurationRuntime.Snapshot.wildContext(policy)` создаёт такой контекст
только с явной политикой. Reload влияет на будущие предложения; replay удерживает
старые значения и определения, а не один номер revision.

Алгоритм `genesis:wild_genome@2` закрепляет следующий RNG-контракт:

- SHA-256 от UTF-8 `genesis:wild_rng_v1\0`, signed big-endian i64 seed,
  исходного вида и имени потока. Каждая из двух строк записывается как
  big-endian i32 длина UTF-8 в байтах, затем сами байты;
- первые восемь байтов SHA-256 трактуются как signed big-endian i64 для
  `java.util.Random` LCG48, используется один `nextDouble()`;
- независимые потоки: namespaced gene ID, `arcana_gate`, `arcana_awake_pair`.
  HERITAGE не расходует RNG; условная ARCANA-пара выбирается только при пробуждении;
- пары сортируются по ContentId первой и второй копии, интервалы полуоткрытые.
  Сравнивается точное binary64-значение через BigDecimal, без раннего округления.

Идентичности NPC/candidate не заменяют seed и не участвуют в RNG. Выдачу
надёжного seed и привязку к первому осмотру обеспечит интеграция. Потоки не
изменяют прежний GenerationSeed scheme 1; изменение весов одного гена не
потребляет броски ARCANA/ELEMENT. Повтор с неизвестной версией алгоритма запрещён.

Fingerprint политики использует отдельный бинарный профиль
`genesis:wild_distribution_binary_v1`: length-prefixed строка профиля, ID/версия
политики, ID/версия/SHA-256 geneSchema, число видов, затем виды по ContentId.
Для вида записываются ID, число обычных генов, их ID/таблицы по ContentId и
условная ARCANA-таблица. Таблица содержит число пар, затем по порядку пару ID
и десятичный вес `stripTrailingZeros().toPlainString()`. Все длины/версии/счётчики
— big-endian i32. Вес имеет scale в пределах ±1024. SHA-256 считается по всему
потоку; входные коллекции скопированы. Другие веса под тем же ID/версией дают
другой pin. Это внутренний профиль, не канонизация исходных JSON и не RFC8785/GEN1.

## Повторный осмотр и сохранения

[WildCandidateRecord](../src/main/java/dev/ifelse/zirion/genesis/core/wild/WildCandidateRecord.java)
хранит неизменяемые геном/форму и replay с первоначальным запросом/контекстом.
`observe(request, existing)` возвращает тот же объект существующей авторитетной
записи при совпадении NPC и исходного вида. Новые candidateId, seed, affinity,
частоты или reload не перебрасывают геном. Чужой provider/world/entity либо
несовпадающий вид дают отказ. Другого игрока в ключе кандидата нет.

`NpcIdentity(provider, worldId, entityId)` — требование к будущему адаптеру.
Стабильность реального Hytale ID через выгрузку/рестарт ещё должна быть доказана
в 0A; transient ECS index сюда не подходит. Сам класс не является доказательством.
Генерация без existing создаёт только предложение: одновременные первые осмотры
ещё не защищены уникальным ограничением/CAS. В 2A нужно атомарно выбрать одну
запись по постоянному NPC-ключу, вернуть победителя остальным запросам, сохранить
геном и исходные replay-входы и восстановить их после рестарта. Сериализация
записи/журнала, durable uniqueness, безопасное принятие того же NPC и активация
в мире этим механизмом не реализованы. Не генерировать заново вместо lookup.
