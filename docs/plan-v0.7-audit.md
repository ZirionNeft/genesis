Дата: **23.10.2026**, после первой актуализации плана по v0.7.
Основание: [RU GDD](../specs/Genesis_GDD_v0.7/Genesis_GDD_RU_v0.7.md), нормативные
каталоги/Server Config, [карта расхождений](gdd-v0.7-reconciliation.md),

[план](implementation-plan.md) и [AGENTS.md](../AGENTS.md).

## Вывод проверки

В первом варианте нового плана были пропуски в подготовке и порядке реализации.
Необходимые функции часто упоминались только как зависимость или финальная
проверка, без шага, создающего их. Добавлены **0A, 1V, 2D** и задачи внутри
существующих этапов. Все новые шаги TODO; аудит не означает их выполнение.

Свидетельств, требующих отменить DONE основы или D01, не найдено. D01 остаётся
принятым ограниченным стендом; он не покрывает принятие ванильного NPC,
начальный геном, новые возрастные модели и реальные функции спутника.
Core IN_PROGRESS означает наличие старого прототипа и начатую программу
перехода; реализация baseline v0.7 всё ещё TODO.

## Порядок и точки допуска

| Шаг | Что необходимо перед ним | Что остаётся после него |
| --- | --- | --- |
| 1: чистое ядро/конфиг | Нормативные данные; конфликты не трактовать молча | Реальные NPC/ассеты/store ещё не готовы |
| 0A: проверки API | Закреплённый артефакт и контролируемые проверки сервера/клиента | Отдельное производство ресурсов и gameplay |
| 1V: первый набор | Согласованный дизайн, визуальный контракт 1, нужные выводы 0A | Расширение контента/клипов по группам и ролям |
| 2A: состояние | Контракты 1 и нужные выводы ECS/store из 0A | Пользовательские действия и мир ещё подключаются в 2B |
| 2B: первый детёныш | Взрослые исходные кандидаты, безопасное принятие, конфиг/операции/анализ/условия и infant binding | Рост потомка и следующее поколение принимаются в 2C |
| 2C: повторяемый цикл | 2B и все возрастные bindings первого набора | Полные роли/эффекты и обучение принимаются отдельно |
| 2D: роли/способности | Базовый 2C, соответствующие API/rig/клипы | Общая балансная/сетевая/нагрузочная приёмка |
| 3: исследование/гайд | Наблюдение/анализ 2B, базовый 2C; 2D для зависимых заданий | Полная проверка темпа реальными игроками |
| 4: приёмка | Реализованные 1/1V/2A–2D/3 и проверенные нужные пути 0A | Только подтверждённые ограничения выпуска, без подмены TODO результатами тестов |

Это частичный порядок: 0A, чистое ядро и согласование дизайна можно вести
независимо. Не требуется завершить арт всех 28 форм до проверки первой пары.
Роль/вид/возраст включаются только после проверки их собственных зависимостей.

NPC. Если вид отсутствует, положительная игровая поддержка остаётся недоступной;
PASS проверки отказа не является PASS реализации этого вида.

## Пределы проверки

Проверены тексты, дерево исходников/ресурсов и существующие отчёты.
В коде сохраняются только старый Core и prototype-команда/UI; новых конфиг-loader,
WildCandidateRecord/store/возрастного workflow/ролей не обнаружено.
Java, GDD JSON и игровые ассеты не изменялись; сервер/клиент и сборка заново
не запускались. Для документационных изменений проверяются локальные ссылки,
согласованность идентификаторов этапов и отсутствие whitespace-ошибок.
