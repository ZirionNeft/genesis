актуальный статус и ближайшее действие — в [AGENTS.md](../AGENTS.md).

Действующие уточнения дизайна/роста — в [художественном ТЗ](canid-art-direction.md):

## Принятое решение ADR-001 и изменения v0.5

**Статус: ACCEPTED, 15.10.2026; основание: GDD §§18, 21.1, 23.1, 24.**
Принцип совместимости уже принят спецификацией; технические способы его
реализации остаются открытыми (D13–D15). Ни один пункт ниже не считается
реализованным только из-за обновления плана.

- Логические границы: чистое Java-ядро → версионируемый Public API с immutable
  DTO → Hytale/gameplay. Ядро не импортирует Hytale и сторонние моды; основной
  адаптер Hytale не импортирует сторонние моды. Интеграции поставляются отдельно
  и зависят от Genesis Public API; основной manifest не ссылается на такие моды.
  Один JAR Genesis допустим; полный сторонний API и готовые адаптеры не нужны в MVP.
- У NPC один `primaryControllerId`; `playerOwnerId` и provenance — отдельные
  понятия. Маркер `GenesisCreatureComponent` добавляется только созданному Genesis
  существу или после подтверждённого принятия управления. Имена компонентов GDD
  концептуальные; действительный ECS API ещё нужно проверить.
- Нет массового присвоения ванильных животных при загрузке/сканировании мира.
  Контакт с диким ванильным NPC начинается явным действием игрока Genesis;
  известный чужой питомец или незарегистрированный чужой вид не перехватывается.
  Неизвестное происхождение не означает свободный контроль: при риске конфликта
  нужен консервативный отказ. Универсальное распознавание любых модов не обещается.
- Genesis пишет только свои данные, не удаляет чужие ECS-компоненты и не
  перезаписывает чужие баффы. Основные AI, модель/rig/hitbox и инвентарь имеют
  согласованный источник истины; overlays допускаются только в разрешённых слотах.
  Модификаторы атрибутов учитываются по namespaced source ID и идемпотентно
  восстанавливаются/снимаются. Поддержку Hytale проверить по D13; если её нет,
  выбрать собственный слой согласования или отказ от неподдерживаемой интеграции.
- Определения контента имеют namespaced ID и версии, реестры фиксируются до
  игровых расчётов (`registry freeze`). Публичные snapshots неизменяемы;
  горячая подмена генетических правил без миграции запрещена. Внешнее расширение
  не перезаписывает зарегистрированные ID и `genesis:*` без явного разрешения.
- Ограниченные `Before*` проверки выполняются до расхода/фиксации; их ошибка
  или таймаут дают отказ без расхода попытки. `After*` события публикуют immutable
  результат после commit. Ошибка listener не откатывает рождение и не запускает
  повторный RNG; повтор запроса не создаёт второй результат/набор событий.
  Для надёжных подписчиков рассмотреть outbox/retry с идемпотентностью по ID события,
  не выбирая способ хранения до D02. Обработчики не блокируют tick неопределённо.
- Данные расширений содержат `extensionId`, `schemaVersion` и канонический payload;
  версии обязательных расширений входят в контракт Genesis Code. При отсутствии
  определения исходные байты и метаданные сохраняются как opaque, а зависимые
  скрещивание/мутация/импорт/спавн отклоняются без частичного результата.
  Визуальный fallback разрешён только для явно необязательной косметики без смены
  генома. Checksum не подтверждает provenance; импорт через расширение и
  админ-спавн по умолчанию исключены из первооткрытий.
- Безопасные defaults §24.8: `respectExternalOwnership=true`,
  `allowAutomaticTakeover=false`, `allowExplicitTransfer=false`,
  `conflicts.policy=deny`, `genesisCode.missingExtensions=reject` внутри
  `compatibility`. `deny` отклоняет конкретную операцию, а не отключает мод.
  Отключение интеграций не отключает базовый цикл. Конфликты логируются
  структурированно (`entityId`, `operation`, `otherController`, `reason`, `decision`)
  с минимизацией личных сведений. Эти принципы отделяйте от предварительного баланса.

Расширенный API (`CreatureProvider`, `GeneticsExtension`, `MorphologyProvider`,
`AbilityProvider`, `CompatibilityPolicy`, `GenesisEvents`) — проект контрактов,
а не существующие классы. Минимальную стабильную границу определить по D14;
полные интеграции выпускать поэтапно после MVP. Трансфер NPC между модами
отложен за MVP и требует обоюдного handshake, прав, snapshot, атомарной смены
контроллера и отката без дюпов (D15). Произвольная бесконфликтность не гарантируется.

## Как вести план

- Статусы: `TODO`, `IN_PROGRESS`, `BLOCKED`, `DONE`. У каждого этапа ниже есть
  зависимости и критерий готовности; выполненные задачи отмечайте `[x]`.
- При начале этапа обновляйте статус и ближайший шаг. При завершении записывайте
  дату, результат и подтверждение: тесты, пути к отчётам, серверная/клиентская
  проверка. Не отмечайте игровой этап готовым только по успешной компиляции.
- Блокировку описывайте конкретно: что неизвестно, какая проверка или решение
  её снимает. Независимые задачи можно продолжать, не выдавая допущение за факт.
- Решения с последствиями для сохранений, генетики и публичных форматов заносите
  в реестр ниже: выбранный вариант, причина, дата, затронутые этапы. Открытые
  вопросы не требуют повторного согласования уже разрешённых пользователем действий.
- Новые задачи привязывайте к этапу и разделу GDD. Уточнения пользователя имеют
  приоритет; расхождения фиксируйте здесь. Не расширяйте MVP поздними функциями.
- Подробные результаты длительных исследований можно хранить отдельными файлами;
  в плане оставляйте ссылку, принятое решение и оставшиеся ограничения.

## Объём и зависимости

**Играбельный MVP (GDD §21.1):** Клыкастые, волк и лисица, один гибридный
архетип; 12 независимых диплоидных локусов с небольшими полными таблицами
экспрессии; несколько полезных и вредных мутаций; приручение, короткая «Гармония»,
вольер, Искры и Колыбель, взросление, базовый спутник, Genesis Code, сохранения
и настраиваемый инбридинг. Для игрока должен работать весь цикл без отладочных
команд. Минимальная карточка, выбор пары и действия с Искрами входят в MVP;
полная лаборатория, рекомендации и регистрация пород — следующий этап.

**Обязательная совместимость MVP (GDD §§20.1.1, 21.1, 24.9):** автономный
запуск и весь базовый цикл без внешних модов; явная принадлежность собственных
NPC; отсутствие глобального перехвата и записи в чужое состояние; идемпотентные
попытки/события; сохранность нераспознанных данных расширений и безопасный отказ
зависимых операций. Проверки распределены по этапам 1–2C ниже.

До завершения MVP не включаем четыре полные группы, все хозяйственные линии,
уникальные магические анимации, рынок, межгрупповые гибриды, глобальные Хроники
и внешний сайт; также полный API сторонних видов, готовые интеграционные адаптеры
и трансфер NPC между модами. Не вводим обязательную смерть от старости по умолчанию.

## Этап 2B — полный игровой цикл Клыкастых

Основание: GDD §§3–7, 10, 13, 17, 21–22, 24.3–24.4, 24.6. Зависимости: 0, 1, 2A.

- [ ] Добавить волка, лисицу и гибридный архетип с согласованными моделями,
  анимациями, ролями NPC, стартовыми геномами и способом появления в мире.
- [ ] При создании Genesis-существа или подтверждённом принятии управления
  назначать явный маркер/controller; не добавлять компоненты всем NPC при загрузке.
  До приручения/разведения проверять известные сигналы чужого контроля и права;
  отказывать чужим питомцам/незарегистрированным видам и при риске неопределённости.
  Контакт с ванильным диким NPC запускается только явным действием игрока.
- [ ] Реализовать наблюдение → контакт → привязанность: честные сигналы,
  `trust/fear` в `[0,100]`, реакцию на темперамент и частичное сохранение доверия
  после неудачи. Сохранять открытые сведения бестиария и владельца.
- [ ] Добавить минимальные вольер и Колыбель, согласованные рецепты/стоимость,
  выбор пары и объяснения отказа: возраст, доступность, группа/rig, родство,
  готовность, среда, материалы и место результата.
- [ ] Реализовать три раунда «Гармонии» с пошаговым режимом без таймера и
  отключением мини-игры настройкой сервера. UI показывает отдельно успех
  попытки и вероятность целевого генотипа, не обещая скрытых генов.
- [ ] Подключить Искры: сохранение, доступный уровню анализ, рассеивание,
  воплощение в детёныша. Не создавать NPC и AI-тики для хранимых Искр.
  Подтверждать необратимое рассеивание ценных/избранных образцов.
- [ ] Связать фенотип с внешностью и параметрами NPC, не подменяя неизвестные
  игроку сведения полным серверным геномом в UI или сетевых ответах.
- [ ] Применять генетические атрибуты по source ID с идемпотентным reload/снятием,
  сохраняя чужие бонусы; не выставлять абсолютные значения каждый tick. По D13
  выбрать поддержанный Hytale механизм или собственный слой согласования/отказ.
  Не назначать конкурентные AI, основную модель/rig/hitbox и контейнер инвентаря;
  overlays допускать лишь через согласованные слоты.

**Готово, когда:** игрок проходит цикл от двух диких производителей до гибрида
через игровые взаимодействия; Искра не меняется от анализа и не перебрасывается
при воплощении. Подтверждены серверная загрузка контента и внешний вид на клиенте;
контроль локален для Genesis-сущностей, чужие питомцы/компоненты/баффы сохранены.

## Этап 2C — довести и принять MVP

Основание: GDD §§11–15, 17, 19–21, 24.9. Зависимость: 2B.

- [ ] Реализовать рост от молодой особи первого уровня к зрелой форме по
  уровню и опыту питомца, базовое обучение и полезного спутника. Пороги роста,
  число форм и уровни проявления заложенных признаков согласовать по
  [актуальному ТЗ](canid-art-direction.md); уточнение пользователя 18.10.2026
  имеет приоритет перед прежней схемой стадий. Определить минимальный набор
  команд из GDD §13.3. Проверить путь,
  возвращение домой и серверные лимиты активных животных.
- [ ] Добавить минимальную карточку животного, экспорт собственного Genesis Code
  и административное воспроизведение с проверкой прав, версий и входного кода.
  Обычный survival-импорт по умолчанию выключен; админ-спавн/импорт помечаются
  как не участвующие в первооткрытиях.
- [ ] Проверить импорт кода с неизвестным обязательным расширением: понятный отказ
  без частичного NPC/Искры, расхода и подмены генов; fallback только для явно
  необязательной косметики. Проверить отметку provenance внешнего импорта.
- [ ] Проверить совместную игру: конкуренцию за пару/Искру, разрыв соединения,
  повторный вход, выгрузку и перезапуск. Вне активной зоны не выполнять полный
  боевой AI-тик. Зафиксировать нагрузочный сценарий и измерения.
- [ ] Проверить en-US/ru-RU, клавиатуру, режим без таймера, читаемые сигналы
  помимо цвета, настройки эффектов и подтверждения необратимых действий.
- [ ] Выполнить обязательную матрицу совместимости §§20.1.1, 24.9: весь цикл
  только с Genesis и при отключённых интеграциях; нет автоматических изменений
  ванильных NPC; известный чужой питомец и второй controller получают отказ;
  чужие компоненты/баффы не теряются, свой бонус не дублируется после reload;
  удаление адаптера не мешает запуску/сохранениям; удаление расширения сохраняет
  payload и блокирует зависимые операции; повторы запросов и сбой listener не
  создают нового потомства/событий. Использовать контролируемые тестовые сигналы
  или адаптер, фиксируя покрытые API; не обещать совместимость с любым модом
  и не делать выпуск полноценной интеграции условием MVP.
- [ ] Провести плейтест темпа и полезности: первое приручение, первый гибрид,
  понимание вероятностей, стоимость содержания, причины выбора/рассеивания Искр.
  Оценивать медиану и высокий процентиль; не менять наследование ради защиты
  от невезения. Числа GDD пока являются ориентирами.
- [ ] Выполнить `clean build`/`verifyPluginJar`, содержательные тесты ядра и
  сохранений, запуск на 0.7.2 и клиентскую приёмку полного цикла. Обновить README
  по фактически доступным действиям; перечислить ограничения MVP.

**Готово, когда:** весь состав MVP работает после перезапуска и в мультиплеере,
гибрид полезен игроку, дюпы и критические проблемы цикла закрыты, обязательная
матрица совместимости пройдена, а результаты проверок записаны. Полный сценарий
§22 проверяется в пределах возможностей MVP; породы и Хроники принимаются на
своих этапах. Гонка первооткрытий из §24.9 проверяется в этапе 5 при появлении
Хроник; метаданные происхождения и исключение импортов закладываются уже в 2A–2C.

## Этап 3 — целенаправленная селекция

Основание: GDD §§7, 12, 14, 17, 20. Зависимость: 2C.

- [ ] Развить бестиарий, лабораторию и уровни анализа: неизвестные гены показывать
  как неизвестные/интервалы. Добавить журнал целей и объяснимые рекомендации пар.
- [ ] Показать родословную, поколение, доли происхождения и риск родства;
  доли происхождения не дают дополнительных бонусов к характеристикам.
- [ ] Реализовать критерии стабильности и регистрацию пород, учёт оценённых
  потомков и производителей. Порода не меняет наследование; опциональный бонус
  относится только к успешности попытки.
- [ ] Открывать инструменты по прогрессии: ускоренное приручение изученного вида,
  автоматическое разведение освоенной группы, улучшение Колыбели и фильтры.
  Авто-режим не выгоднее правильно выполненной ручной мини-игры; фильтры видят
  только доступные игроку сведения. Проверить несколько вольеров и общую пару.
- [ ] Добавить дикие линии-носители как альтернативу массовому разведению;
  проверить стоимость циклов и отсутствие прибыли от рассеивания/повторных попыток.

**Готово, когда:** игрок может спланировать и закрепить целевую комбинацию,
понимает прогноз и риск, регистрирует породу по проверяемым критериям; автоматика
снижает рутину без раскрытия скрытого генома и изменения вероятностей аллелей.

## Этап 4 — роли, новые группы и баланс

Основание: GDD §§4, 9–11, 13–14, 20–21. Зависимость: 3.

- [ ] Расширять контент по одной группе: Бегуны, Тяжеловесы, Крылатые. Для каждой
  до включения проверить rig, все допустимые экспрессии, модули, анимации,
  коллизии, локализацию и воспроизводимость Genesis Code.
- [ ] Добавлять роли последовательными игровыми срезами: бой/защита, маунты,
  переноска, разведка, хозяйство, поддержка. Сохранять одну основную специализацию;
  седло, груз и полёт требуют реальной анатомической и API-поддержки.
- [ ] Подключить способности, снаряжение, физиологические расходы и влияние среды;
  обучение и состояние не наследуются. Не учитывать один эффект дважды.
- [ ] Проверить инвентари при выгрузке/смерти/переносе, лимиты спутников,
  производственные циклы с кормом и временем; PvP оценивать отдельно от PvE.
- [ ] Провести симуляции и Парето-анализ ролей, биомов и экономики: не должно быть
  дешёвого доступного генотипа, лучшего во всех сценариях. Калибровать реальные
  HP/скорость/урон в игре, не переносить условную шкалу 0–100 напрямую в API.

**Готово, когда:** каждая добавленная группа проходит полный цикл, роли дают
разную полезность с понятной ценой, результаты симуляций подтверждены плейтестами.
Межгрупповые гибриды остаются вне этого объёма без отдельного требования.

## Этап 5 — Хроники, авторство и внешние инструменты

Основание: GDD §§12, 14–18, 20–21, 24.7, 24.9.
Зависимость: 3; контентные расширения — 4.

- [ ] Определить ключи поддерживаемых архетипов/редких форм и локальные Хроники;
  уникальная комбинация генов сама по себе не становится новым видом/открытием.
- [ ] Регистрировать первенство при физическом воплощении атомарно по
  `(worldId, discoveryKey)`. Различать селекционера, первооткрывателя, основателя
  породы и владельца по UUID; импорт (в том числе через расширения) и админ-спавн
  по умолчанию исключить. Интеграции не переписывают provenance чужой линии;
  controller NPC не получает авторство автоматически.
- [ ] Реализовать историю линий/пород, правила имён и передачи Искры; проверить
  гонку двух первых воплощений и неизменность заслуг при смене владельца.
- [ ] Добавлять передачу/обмен и рынок только после решения о приватности генов,
  правах и сохранении provenance; не переносить авторство вместе с владением.
- [ ] Документировать формат кода, версии RNG/ruleset и общие тестовые векторы
  для внешнего калькулятора, включая namespaced ID и canonical extension payload.
  Отдельную реализацию JavaScript/TypeScript/WASM
  проверять по тем же векторам; разработку сайта выделить в отдельную задачу.

**Готово, когда:** первенство проверяемо в рамках сервера, обмен не подменяет
происхождение, согласованные операции воспроизводятся внешними инструментами.
Глобальные таблицы и криптографически подтверждённый межсерверный паспорт —
отдельное будущее расширение, checksum его не заменяет.
