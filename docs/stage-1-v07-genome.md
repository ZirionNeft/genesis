# Этап 1: модель генома и наследование v2

Дата: **25.10.2026**. Статус: чистая модель и обычное наследование реализованы;
этап 1 остаётся IN_PROGRESS. Основание: GDD v0.7 §§2–4, Gene Schema v2 и
определения семейных вариантов Content Catalog. Новый контур находится в
`core.genetics.v2`, отдельно от прежнего 12-локусного прототипа.

## Модель

| Тип | Контракт |
| --- | --- |
| [RegistryFingerprint](../src/main/java/dev/ifelse/zirion/genesis/core/genetics/RegistryFingerprint.java) | Точный namespaced registry ID, версия и 64 строчных hex-символа SHA-256; сам хеш не вычисляет и подлинность не доказывает |
| [GeneDefinition](../src/main/java/dev/ifelse/zirion/genesis/core/genetics/v2/GeneDefinition.java) | Namespaced ID, непустой immutable-набор вариантов и kind TRAIT/HERITAGE |
| [FamilyGeneSchema](../src/main/java/dev/ifelse/zirion/genesis/core/genetics/v2/FamilyGeneSchema.java) | Immutable-определения одной группы, три исходных вида и ровно три HERITAGE-гена |
| [Genome](../src/main/java/dev/ifelse/zirion/genesis/core/genetics/v2/Genome.java) | Fingerprint gene schema v2, family ID, упорядоченная immutable-map gene ID → диплоидная пара |

Используются существующие нейтральные `ContentId`, `AllelePair`, `RulesetVersion`
и RNG-интерфейс. Новые core-классы зависят только от JDK и чистых типов Genesis.
Новых библиотек или Hytale-импортов в Core нет. Стабильный Public API этим
пакетом не объявляется.

Варианты принадлежат конкретному гену: `genesis:normal` допустим одновременно
у BODY_FRAME и MUSCLE, но `genesis:strong` не становится от этого допустимым
у BODY_FRAME. Отдельного глобального уникального ID аллеля из старого enum нет.
Коллекции глубоко копируются и доступны только для чтения; пары сохраняют
обе копии в каноническом порядке. Добавление зарегистрированного namespaced
trait не требует изменения enum; оно требует соответствующей новой идентичности
реестра, загрузки/проверки определений и последующей проверки зависимых операций.

`FamilyGeneSchema.createGenome` проверяет полный набор генов, варианты каждой
пары, family и точное совпадение registry ID/версии/хеша. Прямой конструктор
`Genome` создаёт структурный snapshot; перед расчётом его всегда проверяет
семейная схема. Неполный набор, лишний семейный ген, неизвестный вариант,
другая группа или другой хеш отклоняются.

Поддерживается только версия **gene schema 2**. Она не выводится из имени
транспорта GEN1 или ревизии canids_draft@2. Старые Genome/codec не конвертируются
и не принимаются новой моделью автоматически.

## HERITAGE

Обязательны `genesis:heritage_1`, `genesis:heritage_2`, `genesis:heritage_3`
с kind HERITAGE. Варианты каждого из них в точности равны трём исходным видам
группы. Нельзя отметить один из этих генов обычным TRAIT, подставить основателей
другой группы или объявить четвёртый HERITAGE-ген. `mutationAllowed()` для них
возвращает false; игровая система мутаций v2 ещё не реализована.

`founderCopyCounts` возвращает только положительные количества исходных копий,
суммарно шесть. Это исходные данные для phenotype и
[реализованного effective-form resolver](stage-1-v07-forms.md),
а не проценты родословной и не исторический граф. Например:

- чистые wolf × fox дают по одной wolf/fox-копии в каждом HERITAGE-гене → 3:3;
- обратное скрещивание может дать 6 wolf и 0 fox;
- исторические корни линии при этом задаются отдельно будущим hybridGraph resolver.

Возраст/XP/владелец/creatureId, родословная, историческая форма, знания игрока
и эффекты роли не входят в геном. Дополнительного frailty/kinship gate в новом
обычном наследовании нет.

## Порядок наследования и replay

[MendelianInheritance](../src/main/java/dev/ifelse/zirion/genesis/core/genetics/v2/MendelianInheritance.java)
сначала проверяет обоих родителей целиком. При отказе не расходуется ни один
выбор RNG. При допустимых входах берётся одна из двух копий A и одна из двух
копий B на каждом гене, включая HERITAGE.

Внутренний algorithm ID: `genesis:mendelian_gene_id_order_v2`.
Гены обходятся по `ContentId.compareTo`: namespace, затем path; внутри гена
сначала A, затем B. Всегда два выбора на ген, включая гомозиготы: **52 / 54 /
54 / 56** для четырёх стартовых групп. Выходные пары снова канонизируются.
Порядок вставки исходных map не влияет на replay.

Добавление гена меняет расход RNG. Для точного воспроизведения необходимы
те же определения/fingerprint, алгоритм и состояние выделенного RNG-потока.
Здесь проверяется прямой `SeededAlleleRandom`. Следующим пакетом 25.10 добавлен
[workflow до мутаций](stage-1-v07-breeding-workflow.md): GenerationSeed, удержанный
контекст правил и replay. Durable фиксация исхода/операции ещё TODO в 2A. Этот алгоритм не изменяет старый enum-order v1.

## Проверки и нормативные данные

`V2TestContent` читает **настоящие** Gene Schema, Server Config и семейные
варианты Content Catalog через уже доступный тестовый Gson. Полных таблиц генов
и балансных defaults в production Java не дублируется. Эти три файла объявлены
inputs Gradle test, путь передаётся от project directory, без машинного пути.
Здесь Gson используется тестовой fixture, не моделью Core; последующий
[Java-loader](stage-1-v07-runtime-config.md) применяет его в отдельном адаптере.

На данных определений проверены 26/27/27/28 пар и наличие HORN/WING/BEAK в
соответствующих семейных схемах. После согласованного исправления V07-01
25.10.2026 исходный пакет принят отдельными Python-валидатором и Java-loader;
тесты генома не заменяют проверку полного набора или игровых bindings.

13 тестов модели и семь наследования, всего **20 новых JUnit-тестов**, проверяют:

- полные семейные наборы и gene-scoped варианты, пропущенные/лишние гены,
  ошибочные family/fingerprint/версии и недопустимые HERITAGE;
- защитные копии/immutable-коллекции, равенство при разном порядке map,
  добавление синтетического namespaced trait без изменения enum;
- 3:3 от чистых родителей, потерю линии при backcross, два выбора на каждый
  ген всех групп и нулевой расход RNG при любом недопустимом родителе;
- независимый полный [Python-вектор](../src/test/python/v2_inheritance_vector.py)
  и [properties fixture](../src/test/resources/inheritance-v2-vector.properties):
  порядок всех 26 генов, 52 RNG-выбора и каждая пара потомка при seed 42;
- 20 000 потомков с фиксированным seed: частоты 1:2:1, независимость двух генов
  и сохранение суммарных шести HERITAGE-копий; допуск шесть биномиальных sigma.

Генератор вектора не зависит от Java/кодека и использует собственный LCG48.
Его вывод сохранён в test resources; Python не нужен для обычного Java test.
Вектор описывает наследование тестовых гетерозигот, не распределение дикой
популяции и не правило выбора признаков игроком.

25.10.2026: `build verifyPluginJar testGddCatalogValidator` — BUILD SUCCESSFUL;
**169 JUnit-тестов выполнены**, 0 failures/errors/skipped, плюс 33 Python-теста
