## Доли происхождения

`SpeciesAncestry` хранит доли исходных видов по namespaced ID и отдельную
`unknownShare`. Все доли неотрицательны, в сумме ровно 1, используются точные
BigDecimal. Вход копируется, нулевые записи убираются, представление канонизируется.

`childOf(a,b)` усредняет каждый вид и неизвестную долю: волк × лисица даёт
50/50; гибрид × волк — 75/25. Волк × неизвестное происхождение даёт 50% волка
и 50% неизвестного; известная часть не нормализуется до 100%.
Эти доли не добавляют характеристик и не выводятся из похожести геномов/моделей.
Ownership, primary controller, доказательство provenance и история события
по ADR-001 остаются отдельными данными этапа 2A.

## Граф родословной

`PedigreeEntry` содержит UUID особи, Optional UUID двух родителей и явный
`referenceFounder`. Неизвестный родитель и отсутствующая запись известного
UUID не превращаются автоматически в независимого основателя.

`founder(id)` означает **доверенное допущение модели**: особь входит в исходную
популяцию неродственных, неинбредных основателей. `unknown(id)` означает отсутствие
сведений. Какие дикие/импортированные особи получают статус основателя и по каким
данным, должен определить будущий игровой слой. Отсутствия записи недостаточно.

`Pedigree` копирует записи и проверяет весь граф: повтор UUID, родитель равен
самой особи, два одинаковых родителя и любой цикл запрещены. Не найденные
записи родителей допустимы как явная неполнота. Топологический порядок
итеративный, не зависит от порядка регистрации или перестановки родителей.
`generation(id)` возвращает 0 для reference founder, иначе 1+max родителей
при известном поколении обоих; при неизвестных данных — OptionalInt.empty.

Хранение здесь только в памяти. Это не решение о базе данных, архиве,
удалении старых поколений или загрузке графа из мира.

## Расчёт родства

`Pedigree.ALGORITHM_VERSION=1`. Возвращается коэффициент kinship `phi(a,b)`,
который равен F их потомка. Он не равен удвоенному коэффициенту relationship.

Рекурсия для родителей p/q: `phi(i,j)=(phi(p,j)+phi(q,j))/2`;
диагональ `phi(i,i)=(1+phi(p,q))/2`. У reference founders диагональ 0.5,
между разными основателями 0. Формулы сверены с
[первичной документацией kinship2, TM Therneau](https://cran.r-project.org/web/packages/kinship2/vignettes/kinship_code_details.html).
Используется топологически упорядоченная симметричная матрица и точная арифметика
BigDecimal. Уже инбредные предки учитываются своей диагональю, не константой 0.5.

По умолчанию исследуются предки на расстоянии до **4 рёбер** от любого из двух
родителей. Собирается объединение UUID, поэтому общий предок сохраняет одну
личность. Известные связи между уже включёнными UUID сохраняются, даже если
один из путей к ним длиннее лимита. При четырёх поколениях не более 62 UUID.
Предел отдельного расчёта — **512 узлов**: превышение даёт явную ошибку
до выделения матрицы, без молчаливого усечения. Глубина задаётся параметром;
отрицательное значение запрещено. Проверка длинного исходного графа не рекурсивна.

`Estimate` содержит lowerBound, upperBound, причины неопределённости,
число рассмотренных UUID и заданную глубину. Возможны UNKNOWN_PARENT,
MISSING_RECORD и DEPTH_LIMIT. При неполноте нижняя оценка считает нераскрытые
ветви независимыми/неинбредными; известные общие UUID продолжают учитываться.
Верхняя граница консервативная, 1: это широкий допустимый предел, не доверительный
интервал и не утверждение максимального риска именно этой пары.
При полноте границы равны; точность условна относительно явно принятых основателей.

Математический запрос `kinship(a,a)` разрешён для проверки диагонали. Право
разводить одну и ту же особь этим не предоставляется; проверка пары — будущий workflow.

## Политика инбридинга и врождённая ослабленность

`InbreedingPolicy` — immutable входы: mode, FrailtySettings и Restrictions.
Проверяются конечность и диапазоны вероятностей, порогов, штрафа HP и лимита F;
множитель K может быть больше 1, но не отрицательным/бесконечным.

- OFF возвращает нулевой риск и допуск по ветке инбридинга независимо от
  frailty.enabled, запрета родственных пар и maxCoefficient. Дополнительных
  штрафов, запретов или RNG ослабленности нет. Поля конфигурации всё равно
  должны быть валидными; остальные игровые условия остаются внешнему workflow.
- SOFT использует значения §19: enabled=true, F0=0.0625, K=0.2, Pmax=0.15,
  healthPenalty=0.08; allowRelatedBreeding=true, maxCoefficient=0.5.
- STRICT требует явно переданных FrailtySettings/Restrictions. Скрытого
  усилителя риска или выдуманного численного preset нет.

Для обоих включённых режимов независимые ограничения из конфигурации действуют
явно: allowRelatedBreeding=false требует F=0, иначе F<=maxCoefficient.
Граница maxCoefficient включительна. Отключение frailty.enabled отключает
ослабленность, сохраняя настроенные ограничения пары; OFF отключает оба механизма.

`InbreedingRules.assess` не расходует RNG и возвращает:

- Allowed с точной вероятностью ослабленности и штрафом;
- Rejected, если уже известная нижняя оценка превышает ограничение;
- Indeterminate, если интервал не позволяет проверить ограничение или получить
  точный риск. Это не допуск к расходу ресурсов. Будущий workflow должен
  получить достаточные данные/явно обоснованный профиль основателей или отказать.

При частичной родословной допуск возможен, если решение не зависит от неизвестной
части: например, ограничения сняты и ослабленность выключена либо её риск
на всём интервале уже равен одной и той же верхней отсечке. Признак неполноты
при этом сохраняется. Политика не подставляет нижнюю оценку вместо истинного F.

Риск `min(Pmax, K*max(0,F-F0))` считается BigDecimal без промежуточного overflow.
При F=0.25 мягкий режим даёт **0.0375**, при F<=0.0625 — 0.
`roll` принимает только Allowed: нулевой риск не потребляет RNG, положительный
делает один draw в [0,1), эффект возникает при draw<P. При эффекте фиксируется
healthMultiplier=1-healthPenalty (0.92 по начальному профилю), иначе 1.

`FrailtyOutcome` — неизменяемое врождённое состояние конкретной особи, отдельно
от Genome/наследственных аллелей/Genesis Code. Последующая смена настроек
не изменяет уже полученный результат. Хранить его и обеспечить ровно один
розыгрыш на birth ID предстоит этапу 2A; здесь нет события, UUID рождения или
идемпотентной транзакции. Параметры наследования/мутации этот пакет не принимает.

Выделенный поток `SeededFrailtyRandom`: обычный Java Random/nextDouble, ID
`genesis:frailty_java_random_lcg48_v1`, 48-битное состояние. Схема получения
отдельного seed из birth seed остаётся задачей D11; поток не следует совместно
расходовать на наследование, мутацию или шанс попытки.

## Проверки

23 новых теста: 4 происхождения, 8 графа/родства, 11 политики/ослабленности.
Подтверждены все пять случаев GDD при неродственных основателях:

| Пара | F потомка |
| --- | --- |
| Неродственные | 0 |
| Двоюродные | 0.0625 |
| Единокровные | 0.125 |
| Родитель × потомок | 0.25 |
| Родные брат × сестра | 0.25 |

Дополнительно: потомок родных брата/сестры имеет self-kinship=0.625;
двое их детей — phi=0.375; такая инбредная особь с собственным потомком от
неродственного партнёра — phi=0.3125. Проверены неполные записи и общий
неразрешённый UUID, глубина/восстановление полноты, порядок/snapshots, циклы,
цепочка 5000 поколений без рекурсии, превышение бюджета, off/soft/strict,
неопределённый риск, границы RNG, cap/экстремальные значения и неизменность
врождённого состояния после смены настроек.

Две независимые симуляции по **100 000** случаев:

- Передача помеченных копий аллелей через два поколения, включая скрещивание
  родных брата и сестры,
  и сравнение случайных копий у двух потомков (gene dropping): частота IBD
  согласуется с phi=0.375, без использования матричной рекурсии в симуляторе.
  Seed `0x5045444947524545`.
- Ослабленность при F=0.25: частота согласуется с P=0.0375, с ожидаемым HP-множителем.
  Seed `0x465241494C54594C`.

В обоих случаях допуск — 6 биномиальных sigma `sqrt(N*p*(1-p))`.
