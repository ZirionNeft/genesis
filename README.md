# Genesis

Мод для **Hytale 0.7.4**. Разработчик — **Zirion**, издатель — **if-else.dev**.

Основа — серверный Java-плагин с журналированием запуска и остановки.
В JAR также включён asset pack с простым тестовым NPC для проверки моделей.
Добавлен стенд модульной анатомии и начат независимый Genesis Core. Прежний контур:
расчёт шанса попытки, 12-локусный геном, фиксируемый каталог аллелей/экспрессии
и независимое наследование с воспроизводимым seed. Добавлены определения
групп/видов/rig, проверка совместимости и предварительный ruleset волка/лисицы.
Ядро пока не подключено к игровому разведению.

Актуальная спецификация — [GDD v0.7](specs/Genesis_GDD_v0.7/Genesis_GDD_RU_v0.7.md)
и нормативные JSON рядом с ней. Прежний контур ядра — **прототип v0.5**:
12 локусов, старый бинарный GEN1 и canids_draft@2 ещё не перенесены на новую
схему v2/HERITAGE и JSON/Base64url/CRC32 GEN1. Старые frailty/soft/strict
не входят в актуальный контракт. [Сверка с кодом](docs/gdd-v0.7-reconciliation.md),
[план перехода](docs/implementation-plan.md) и [AGENTS.md](AGENTS.md) отделяют
реализованные механизмы от новых требований.

## Сборка

Нужен **JDK 25**. Используйте включённый Gradle Wrapper 9.6.0:

```sh
./gradlew clean build
```

Результат: `build/libs/Genesis-0.1.0-SNAPSHOT.jar`. Проверка `verifyPluginJar`,
включённая в `build`, проверяет упакованный манифест, наличие класса входа,
ресурсы NPC, анимацию, переводы и отсутствие классов сервера и исходников
Blockbench в моде. Автоматизированных игровых тестов пока нет.
`./gradlew test` проверяет манифест готового JAR настоящим Hytale codec и точную
совместимость `ServerVersion: =0.7.4`, включая отказ для соседних версий.
Также проверяются крепления и геометрия/UV цельного контроля в JAR, формула
вероятности, её пределы и валидация входов; immutable-геном, freeze/таблицы,
наследование, фиксированные RNG-векторы и 100 000 потомков по всем локусам.
Текущий набор — **348 Java-тестов**: 199 проверок нового контура/загрузки/UUID/marker
и 149 прежних. Полный состав — в [плане](docs/implementation-plan.md).
Далее описаны проверки **прежнего прототипа**, включая каталоги/совместимость, цепочки наследования
волка/лисицы, потенциал/эффективность, точный выбор внешности без подмен генома
и одношаговые мутации. Отдельные 100 000 потомков проверяют частоты мутаций;
недоступные варианты явно пропускаются, уже наследственные мутации сохраняются.
Проверяются происхождение, родство, частичные родословные и off/soft/strict;
ещё две симуляции по 100 000 случаев проверяют IBD и отдельную ослабленность.
GEN1 проверяется независимым бинарным вектором, round-trip/лимитами и повреждениями.
Неизвестные данные расширений сохраняются без потерь; зависимый preflight
отклоняется до операции. Точные и текущие определения выбираются явным режимом.
GenerationSeed v1 разделяет пять RNG-потоков; чистый BreedingWorkflow генерирует
потомка только после допуска и успешного draw. Его проверяют независимые Python
seed-векторы и 100 000 попыток. Игровая транзакция/выдача Искры ещё не подключена;
наследование payload расширений пока консервативно отклоняется без потери bytes.
Отдельный кандидат canids_draft@2 добавляет шесть мутаций, полные 54 пары
и три предварительных численных профиля с ценами; исходный v1 сохранён.
Фактическая доступность de novo на базовом геноме — 7% изменений + 1% явного
SKIP. Финальные ассеты для 864 семантических сочетаний пока не зарегистрированы.
Численные профили Клыкастых предварительные; механизм выбора внешности пока
проверяется на тестовых планах. Игровой баланс и реальные ассеты для всех
генетических выходов ещё не готовы.
Прежние художественные концепты и модельные попытки волка забракованы
пользователем и удалены. По v0.7 возраст и XP независимы:
детёныш (~15 мин) → молодая особь (45 мин)
→ взрослый; рост от времени/ухода, оффлайн до 240 мин, XP его не ускоряет.

## Локальный сервер

Получите `Assets.zip` **версии 0.7.4** из обновлённого Hytale Launcher или
официального Downloader. Серверный JAR 0.7.4 Gradle загрузит самостоятельно.
Порядок получения файлов описан в
[официальном Server Manual](https://support.hytale.com/hc/en-us/articles/45326769420827-Hytale-Server-Manual).

```sh
./gradlew runServer -PhytaleAssets="/absolute/path/to/Assets.zip" --console=plain
```

Задача собирает мод, помещает его в `run/mods/Genesis.jar` и запускает сервер
из `run/`, слушая `127.0.0.1:5520` по UDP. Отправка ошибок в Sentry отключена.
Native access для серверных библиотек включён явно.
Конфигурация, логи и сохранения остаются в `run/`, который исключён из Git.
Для авторизации в консоли сервера выполните `/auth login device`.
Подключайтесь клиентом с той же версией игры; остановка сервера — `/stop`.

Для подключения с другого компьютера добавьте `-PhytaleBind=0.0.0.0:5520` к
`runServer`. На другом компьютере укажите локальный IP сервера и порт 5520;
для подключения через интернет пробросьте UDP 5520 на этот IP в роутере
и используйте внешний IP роутера. Оба клиента должны иметь версию 0.7.4.
Без параметра `hytaleBind` сервер по-прежнему слушает только `127.0.0.1:5520`.

25.10.2026 цель обновлена с 0.7.2 до **0.7.4**; сборка и серверный запуск
проверены с новой парой JAR/Assets.zip. [Артефакты и результаты](docs/hytale-0.7.4.md).
[История перехода на 0.7.2](docs/hytale-0.7.2.md) и клиентская приёмка D01
сохраняются как прежние свидетельства. Внешность/поведение на 0.7.4 ещё
требуют клиентского прогона.

Для отладки:

```sh
./gradlew runServer -PhytaleAssets="/absolute/path/to/Assets.zip" --debug-jvm --console=plain
```

JVM ожидает подключения отладчика на порту `5005`; в IDEA используйте
Remote JVM Debug. `./gradlew stagePlugin` только подготавливает JAR в `run/mods/`.

Для установки на отдельный сервер скопируйте JAR из `build/libs/` в его `mods/`
и перезапустите сервер. При замене удалите прежний JAR Genesis, чтобы избежать
двух версий одного плагина. На Windows используйте `gradlew.bat`.

## Тестовый NPC

Он стоит на месте, слегка покачивается и поворачивает голову в анимации Idle.
Для демонстрации включены неуязвимость и отсутствие отбрасывания.
Естественный спавн, бой, торговля и награды для него не настроены.

1. Запустите сервер командой из раздела «Локальный сервер» и подключитесь
   клиентом Hytale **0.7.4** по адресу `127.0.0.1:5520`.
2. Для призыва нужны права оператора. В консоли сервера выполните
   `/op add <имя игрока>`, когда игрок подключён. На уже настроенном dev-сервере
   оператору повторно выдавать права не нужно.
3. В игровом чате выполните:

   ```text
   /npc spawn Genesis_TestNPC
   ```

   Это ID NPC-роли; команда создаёт NPC рядом с игроком. Выполняйте её
   на свободной ровной площадке. Для просмотра вариантов команды доступно
   `/npc spawn Genesis_TestNPC --help`. Чтобы NPC появился лицом к игроку,
   используйте `/npc spawn Genesis_TestNPC --facingRotation`.
4. Проверьте лицо и одежду, Idle-анимацию, масштаб и столкновения.
   Сам вызов NPC проверяйте из игрового чата: штатная команда требует игрока
   в мире, даже если указать координаты из консоли сервера.

Исходник: [Genesis_TestNPC.bbmodel](art/models/TestNPC/Genesis_TestNPC.bbmodel).
Превью: [preview.png](art/models/TestNPC/preview.png).
Модельный ассет — `Server/Models/Genesis/Genesis_TestNPC.json`,
NPC-роль — `Server/NPC/Roles/Genesis/Genesis_TestNPC.json`.
Ссылки в ModelAsset задаются относительно `Common/`; `Appearance` в роли
содержит ID ModelAsset. Регистрация этих ассетов через Java не требуется.
