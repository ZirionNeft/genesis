# Genesis: инструкции для агентов

Применяются ко всему репозиторию. Актуализировано **25.10.2026** по GDD v0.7.

## Проект и границы

- **Genesis**, разработчик **Zirion**, издатель **if-else.dev** — https://if-else.dev.
- Цель: **Hytale Release 0.7.4**, мод `0.1.0-SNAPSHOT`, **Java 25**, Gradle Wrapper.
- Спецификация: [GDD RU v0.7](specs/Genesis_GDD_v0.7/Genesis_GDD_RU_v0.7.md),
  [EN v0.7](specs/Genesis_GDD_v0.7/Genesis_GDD_EN_v0.7.md) и **все пять нормативных
  JSON-каталогов** из того же каталога; v0.4/v0.5 и прежние контентные draft — история.
  Серверные значения брать из [Server Config](specs/Genesis_GDD_v0.7/Genesis_GDD_v0.7_Server_Config.json),
  не поддерживать вторую независимую таблицу defaults в документации/коде.
  **Не изменять исходный GDD без прямого поручения пользователя.** Уточнения
  фиксировать в плане/профильных документах, отделяя принятые решения от draft.
- Контракт v0.7: **4 группы × 7 форм = 28**, 12 исходных видов и 112 уникальных
  разрешённых пар. Только внутригрупповое скрещивание; межгрупповое запрещено.
  Историческая форма = объединение корней родителей; генетически проявленная
  форма = реально унаследованные линии. Ни одна из них не является породой игрока.
- Первый игровой срез можно делать на волке/лисице/волколисе, но это порядок
  реализации, **не полная приёмка v0.7**. Старый MVP на 12 локусах больше не контракт.
  Рынок, глобальные Хроники, внешний сайт и трансфер между модами не добавлять
  из старого плана без отдельной задачи. Лицензия и права на ассеты ещё открыты.

В прежнем контуре Core есть детерминированное наследование, frozen namespaced-реестры,
resolver'ы, мутации, родословная, opaque-данные, GenerationSeed и чистый
BreedingWorkflow, **на старой 12-локусной модели**. `canids_draft@2` —
старый контентный кандидат, не `geneSchema v2` из v0.7. Старый GEN1 использует
бинарный payload/Base32/усечённый SHA-256 и несовместим с новым транспортом.
Frailty/soft/strict присутствуют в коде, но не разрешены актуальной спецификацией.
Игровых транзакций, сохранений, приручения, роста, summon/death и стабильного
Public API нет; payload расширений при разведении консервативно отклоняется.
Финальных визуальных планов нет; число 864 относится только к старому draft.

## Генетика и контент v0.7

- Единственная стартовая генетическая модель: `geneSchema=2`,
  `expressionRules=2`, `morphologySet=2`; отдельно `hybridGraph=1` и транспорт `GEN1`.
  Поддержки генетической v1 и провайдера её миграции нет. Старые прототипные
  определения/коды не объявлять совместимыми и не переосмысливать под теми же ID.
- 23 общих гена + семейные + три диплоидных `HERITAGE_1..3`: **26 пар** у
  Клыкастых, **27** у Бегунов/Тяжеловесов, **28** у Крылатых. HERITAGE не мутирует.
  Наследовать по одной случайной копии от каждого родителя для каждого гена.
- База статов — взвешенные показатели **исходных видов** по шести HERITAGE-копиям;
  затем `clamp(1 + ΣpercentDelta, 0.75, 1.35)`, flatDelta, минимум и HALF_UP.
  Скорость — до 0,01 блока/с, остальные шесть показателей — целые.
  Табличные статы гибридов — примеры, не база расчёта. Возраст/роль/обучение/
  состояние/экипировка применяются после генетического потенциала.
- 21 мутация; не более одного нового события на успешное потомство. Категории:
  5% косметика, 4,5% физиология, 2,5% поведение, магия 6/12/22% по исследованию.
  При направленном mastery первое магическое открытие игрока в группе — не позже
  7 подходящих успешных рождений, по точным условиям каталога. Это отдельная
  гарантия v0.7, не разрешение перебрасывать обычное наследование. Мини-игра меняет
  только успех/cooldown. Дополнительных штрафов/запретов за инбридинг нет;
  родословная сохраняется, её доли не заменяют HERITAGE.
- Искра — будущий питомец с фиксированным геномом, не живой NPC и не валюта:
  одна при успехе, слоты Колыбели 16/48, рассеивание без материального возврата,
  неизвестные признаки по умолчанию KEEP, воплощение ровно один раз.
- Новый полный код: `GEN1.BASE64URL_NO_PADDING(UTF8(RFC8785_CANONICAL_JSON)).CRC32_HEX8`.
  Точные ID/версии/SHA-256 реестров обязательны. Публичный паспорт не раскрывает
  скрытые гены; полный код по умолчанию `after_analysis`. Код не даёт права
  бесплатного спавна и не хранит XP/владельца/груз/жизненное состояние.

## Дизайн и рост: актуальные требования

- Модели, текстуры и анимации должны соответствовать art guidelines Hytale
  и быть **как минимум на уровне ванильных**; начальная форма имеет тот же порог качества.
- Прежние концепты, включая progression study v3, и обе художественные попытки
  волка забракованы и удалены. Нового принятого дизайна нет; не восстанавливать
  старый образ как утверждённый. Технический стенд этапа 0 сохранён.
- v0.7 заменяет правило 18.10 о росте от XP: **возраст и уровень независимы**.
  Детёныш — статичная модель около 15 мин; молодая особь — мобильный NPC 45 мин;
  взрослый — роли/разведение/бой; ветеран — мастерство, не старость, adult rig.
  Рост зависит от времени/благополучия/ухода, оффлайн до 240 мин; XP его не ускоряет.
  Уровни 1–30; взрослый уровня 1 допустим. Бонус ухода только на будущее время.
- Геном при росте/обучении не переписывается; опыт не наследуется. Селекция
  новых поколений остаётся второй осью вариативности. Различать скрытое
  носительство и отложенное проявление уже заложенного признака.
- Подходящие ванильные элементы допустимы в начальных формах, авторские
  особенности развиваются вместе с особью. Совместимость частей и анимаций обязательна.
- Семь ролей; два активных ролевых слота, умения на 12/20/28 уровнях. Врождённая
  магия — максимум одна способность из ARCANA + ELEMENT, с возрастным/учебным
  допуском; ролевые умения не наследуются. Follow/Stay/ReturnHome не срываются
  случайно из-за слабой привязанности. Полевой путеводитель — пропускаемый и
  возобновляемый, без бесплатных питомцев и раскрытия скрытых данных.
- Действующее [художественное ТЗ](docs/canid-art-direction.md); подробности
  референсов — [аудит ванильных ассетов](docs/canid-vanilla-reference-audit.json).

## Архитектура и ADR-001

- Первый добровольный осмотр создаёт отдельный `WildCandidateRecord` с фиксированным
  геномом без изменения ванильного NPC. Успешное приручение присоединяет Genesis
  к **тому же** существу после проверки прав/безопасного перехода управления.
  Не создавать копию исходного животного. Непроверенные Role ID/rig/анимации или
  отсутствующий ванильный вид делают его недоступным; каталог не доказывает поддержку.
- Истина — постоянная запись Genesis, NPC — представление: один `creatureId`,
  уникальные Искры/`operationId`, CAS по `revision`, `activationEpoch`, журнал
  операций, durable outbox и reconciliation. ECS и store не одна транзакция.
  Провайдеры: `auto`, `hytale_native`, `sqlite`, `postgresql`; auto выбирает
  проверенный native, иначе SQLite. При сбое не переключаться на пустой store;
  миграция явная, с backup. Равные гарантии целостности обязательны для каждого.
- Dismiss не смерть; summon возвращает того же питомца, активное представление
  одно. По умолчанию summon в бою запрещён, после боя 10 с; проверка до commit
  и до активации. Смерть: `instant` по умолчанию, `revival_station`, `permadeath`.
  Возрождение бесплатно, без Искр/зарядов; `maxRevives=null` без лимита, `0`
  запрещает, положительное число — квота. Считать один раз при успешном
  восстановлении; отзыв квоту не тратит. Геном/XP/навыки/привязанность/груз сохраняются.
- Один JAR допустим: чистое Java-ядро → immutable/versioned Public API → Hytale.
  Core не импортирует Hytale/сторонние моды; основной адаптер не зависит от модов.
  Genesis автономен, обязательные механики работают без внешних интеграций.
- У NPC один `primaryControllerId`; owner и provenance отдельны. Изменять только
  своё состояние. Контакт с ванильным NPC — явное действие игрока; чужих питомцев
  не перехватывать, неизвестное происхождение при риске конфликта даёт отказ.
- Namespaced ID и версии, registry freeze, immutable snapshots; запрет подмены
  зарегистрированных определений/генетических правил без разрешения и миграции.
  Генотип не перебрасывать ради визуализации; обязательная неподдержанная форма даёт отказ.
- `Before*` проверки до расхода/commit; ошибка/таймаут — отказ без расхода.
  `After*` — immutable результат после commit. Повтор запроса не создаёт второе
  потомство/события; ошибка listener не откатывает рождение и не повторяет RNG.
- Неизвестные расширения сохранять побайтово как opaque с ID/версией;
  зависимые операции отклонять. Fallback — только явно необязательная косметика.
  Checksum не доказывает provenance; admin/import исключены из первооткрытий по умолчанию.
- Ограничения прежнего ADR-001 сохраняются, если не противоречат v0.7:
  `respectExternalOwnership=true`, `allowAutomaticTakeover=false`,
  `allowExplicitTransfer=false`, `conflicts.policy=deny`,
  `genesisCode.missingExtensions=reject`. Отказ локален операции; отключение
  интеграций сохраняет базовый цикл. AI/модель/rig/hitbox/инвентарь имеют согласованный
  источник истины; атрибуты по namespaced source ID применяются идемпотентно,
  чужие компоненты/баффы сохраняются. Проверить поддержанный API по D13.

## Разработка и проверка

- Статусы плана: TODO / IN_PROGRESS / BLOCKED / DONE. Обновлять текущий этап,
  ближайший шаг и решения с последствиями для генетики, сохранений и форматов.
  Для DONE нужны дата и свидетельства; успешная сборка не заменяет клиента.
  Подробные исследования/журналы хранить в профильных docs, здесь — итог и ссылка.
- `GenesisPlugin` держать небольшим: регистрация в `setup()`, действия после
  старта в `start()`, освобождение ресурсов в `shutdown()`; игровая логика вне конструктора.
- Использовать регистры плагина, `getLogger()`, `getDataDirectory()` и локализацию.
  Мир/ECS изменять в положенном контексте потока мира; проверять async-контракт
  событий, не блокировать tick диском, сетью или ожиданием futures.
- API/JSON/команды GDD — проектные контракты. Проверять реальные возможности по
  JAR/ассетам целевой версии и клиенту; сначала официальные источники/артефакт,
  затем сообщество. При обновлении заново сверять API и сборки клиента/сервера.
- Манифест в корне JAR, `ServerVersion: =0.7.4`, `IncludesAssetPack: true`.
  Не расширять диапазон без проверки; не добавлять выдуманные поля манифеста.
  Hytale dependency — compileOnly; сервер, Assets.zip, credentials, миры и логи
  не включать в Git/JAR. `run/` — отдельный игнорируемый каталог.
- После Java/Gradle/manifest — сборка и содержательные тесты; после ассетов —
  проверка упаковки, серверной загрузки и клиента. Число тестов не мера арт-качества.

## Пути и инструменты

- Group `dev.ifelse.zirion`, package `dev.ifelse.zirion.genesis`,
  plugin ID `dev.ifelse:Genesis`; версии — `gradle.properties`.
- Java — `src/main/java/`, тесты — `src/test/`, шаблон manifest — `src/main/resources/manifest.json`.
  Hytale JSON — `src/main/resources/Server/`, визуал — `src/main/resources/Common/`.
- ID Hytale-ассетов `Genesis_*` и логические `genesis:*` — разные контракты;
  работающие asset ID не переименовывать механически.
- Blockbench-исходники — `art/models/<Name>/Genesis_<Name>.bbmodel`, экспорты —
  `Common/NPC/Genesis/<Name>/`. В JAR только игровые ресурсы. Один объект с общей
  иерархией/клипами — один проект. [Инструкции моделей](art/models/README.md).
- Перед моделированием через MCP получить `get_capabilities`, проверить
  `hytale_character`; список инструментов обновлять после смены проекта/режима.
  Native Hytale codecs; attachment-root/сокеты и клипы — по принятому D01.
  `hytale_validate_model` проверяет только число узлов/размеры PNG, клиент обязателен.
- Использовать JDK 25 (без preview) и Wrapper. На этой машине рабочий JDK:
  `~/Applications/IntelliJ IDEA.app/Contents/jbr/Contents/Home`; имя Homebrew
  `openjdk@25` ранее указывало на JDK 26 — проверять версию. Машинные пути не коммитить в Gradle.

```sh
./gradlew build verifyPluginJar
./gradlew test
./gradlew stagePlugin
./gradlew testGddCatalogValidator
./gradlew verifyGddCatalogs
./gradlew verifyDevelopment
./gradlew runServer -PhytaleAssets="/absolute/path/to/Assets.zip" --console=plain
```

Две задачи GDD требуют Python 3.10+ и запускаются отдельно от обычного build;
интерпретатор можно задать через `-PpythonExecutable=/path/to/python3`.
Проверка каталогов не содержит исключений для известных ошибок; V07-01 исправлен в источнике.

`runServer`: каталог `run/`, default `127.0.0.1:5520`, сетевой bind через
`-PhytaleBind=0.0.0.0:5520`, стенд через `-PgenesisAnatomyProbe=true`,
read-only диагностика NPC `/genesiscompat` через `-PgenesisCompatibilityProbe=true`
(permission `genesis.prototype.compatibility`),
отдельный изменяющий консольный стенд `/genesisroleprobe` — только с
`-PgenesisCompatibilityRoleProbe=true` и явными `-PgenesisCompatibilityWorldId=...`
и `-PgenesisCompatibilityEntityId=...`; [guards/команды](docs/stage-0-v07-role-marker-probe.md).
debug через `--debug-jvm` (5005, ждёт debugger). Ассеты и сервер одной сборки.
Локальные ассеты: `~/Library/Application Support/Hytale/install/release/package/game/latest/Assets.zip`.
После запуска проверить `/auth status`. Задач `setupHytaleDev`, `updatePluginManifest`,
`hytaleJvmDoctor` здесь нет. Другие команды и запуск — [README](README.md).
